{# Адаптивная строка-таблица (D-13, D-14, UI-06). Обёртки над примитивами data-rowhead / data-row / data-grow, базовые правила которых лежат в app.css, а поведение на узких экранах — в медиазапросах Плана 01. Планы разделов эти макросы только ВЫЗЫВАЮТ и своих классов не добавляют. cols — CSS-значение grid-template-columns, приходит текстом и попадает в пользовательское свойство --cols; так у каждого раздела своя раскладка без новых классов. Импорт: {% from "components/table.html" import rowhead, row_open, row_close, cell %} #} {% macro rowhead(columns=None, cols=None) -%}
{%- for column in columns or [] %}{{ column }}{% endfor -%}
{%- endmacro %} {% macro row_open(cols=None, extra_class=None, id=None) -%}
{%- endmacro %} {% macro row_close() -%}
{%- endmacro %} {# Ячейка. Либо text параметром, либо блочный вызов {% call cell(grow=true) %}…{% endcall %} — во втором случае разметку пишет вызывающий шаблон и она не проходит через параметр строкой. label — подпись колонки, живущая внутри ячейки. Нужна потому, что на 860px шапка колонок скрывается ([data-rowhead] { display: none }), и число в ячейке остаётся без смысла. Правило [data-cell-label] уже лежит в app.css; макрос только эмитит атрибут, и пишет его БЕЗ значения — правило селектирует по наличию атрибута. Контракт подписи: она ДУБЛИРУЕТ название колонки из rowhead, а не придумывает своё. Вызывающий шаблон обязан брать её из того же списка колонок, которым он вызывает rowhead — иначе шапка и подписи разъедутся, и это будет видно только на телефоне. Параметр стоит последним, чтобы позиционные вызовы не сдвинулись, и проходит обычным экранированным выводом: макрос не место, через которое в разметку попадает готовый HTML. #} {% macro cell(text=None, grow=false, mono=false, muted=false, area=None, title=None, label=None) -%} {%- if label %}{{ label }}{% endif %} {%- if text is not none %}{{ text }}{% elif caller is defined %}{{ caller() }}{% endif -%} {%- endmacro %}
