{# Модальное подтверждение (D-18). Прецедента нет ни в приложении, ни в макете: во всём макете ноль модалок и ноль оверлеев, а подтверждения в приложении сегодня сделаны браузерным диалогом. Компонент спроектирован с нуля. Что окно ЗАМЕНЯЕТ: только браузерный диалог. Форма остаётся прежней — тот же маршрут, тот же метод, те же права. Это узкое названное исключение из правила «новый вид, старые действия», а не новая возможность. Открытие — событием окна, поэтому кнопка-триггер может стоять где угодно: {{ modal(id='del-' ~ ad.id, title='Удалить объявление?', action='/ads/' ~ ad.id ~ '/delete', confirm_label='Удалить') }} Доступность: role="dialog" + aria-modal, ловушка фокуса внутри панели, закрытие по Esc и по клику на оверлей, возврат фокуса на элемент, который окно открыл. Начальный фокус ставится на ОТМЕНУ: подтверждение удаления не должно срабатывать по Enter, а отмена не должна быть труднее подтверждения. Слот дополнительных полей формы: макрос можно вызвать блочно, и содержимое блока попадёт ВНУТРЬ формы — после текста и перед кнопками: {% call modal(id='del-bulk', title='Удалить выбранные группы?', action='/groups/bulk', confirm_label='Удалить') %} {% endcall %} Зачем слот: массовое удаление — единственное подтверждение в проекте, где удаляется не одна сущность по идентификатору в маршруте, а НАБОР, приходящий полями формы. Слот предназначен для скрытых полей, а не для произвольной разметки: готовый HTML параметром строкой макрос по-прежнему не принимает — содержимое приходит блочным вызовом из вызывающего шаблона, тем же приёмом, что у cell в components/table.html. Чего слот НЕ меняет: - начальный фокус остаётся на ОТМЕНЕ; появление полей в форме его не сдвигает; - ловушка фокуса собирает элементы запросом по панели, поэтому новые поля попадают в неё сами, и перечисление селекторов переписывать не нужно; - скрытые поля в обход по Tab не попадают: фильтр по видимости их отбрасывает; - метод и маршрут формы прежние.
