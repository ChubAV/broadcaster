Две копии конфигурации держались бы в единстве только бдительностью теста: правка, внесённая в один шелл и забытая во втором, дала бы пользователю РАЗНОЕ поведение слоя письма на экране входа и внутри приложения, а обнаружилось бы это не тестом, а жалобой. Рантайм читает конфигурацию ОДИН раз, при разборе собственного тега: блок, оказавшийся ниже тега, не читается вовсе — молча, без единого сообщения в консоли. Требование «блок стоит выше подключения рантайма» вынесено ВНУТРЬ этого файла, потому что оставленное на усмотрение шелла оно оставалось бы тем, что ломается будущей правкой : достаточно переставить две соседние строки. ПОРЯДОК ПЯТИ ПРАВИЛ responseHandling — САМОЕ ХРУПКОЕ МЕСТО ВЕХИ, И ОН НЕ ПЕРЕСТАВЛЯЕТСЯ. Правила разбираются сверху вниз до первого совпадения, поэтому правило "422" обязано стоять ВЫШЕ общего "[45]..": опустившись ниже, оно перехватывается общим правилом со свапом, выключенным по признаку ошибки. Форма, вернувшая 422 с текстом ошибки валидации, станет для пользователя ПОЛНОСТЬЮ МЁРТВОЙ КНОПКОЙ — нажатие без единого видимого следствия, и без единой записи в журнале. Это самый вероятный способ провалить веху тихо. Ни одно из пяти правил не переставляется, не снимается и не дописывается шестым; порядок утверждается тестом по ИНДЕКСАМ вхождений, а не по наличию правил. JSON оставлен многострочным нарочно: порядок правил обязан читаться глазами прямо в разметке — это же основание, по которому отвергнута сборка блока из словаря Python.
