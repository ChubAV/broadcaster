# Phase 06 — UI Design Contract

> Визуальный и интерактивный контракт фазы. Написан `gsd-ui-researcher`, проверяется `gsd-ui-checker`.

**⚠️ ЭТОТ КОНТРАКТ НАПИСАН ЗАДНИМ ЧИСЛОМ, ПОСЕРЕДИНЕ ФАЗЫ, И ЭТО МЕНЯЕТ ЕГО ПРЕДМЕТ.** Волна 1 (планы 06-01, 06-02, 06-04) уже слита. Гейт `ui.safety-gate` остановил переход к волне 2, потому что контракта не существовало; настоящий документ закрывает разрыв **до** того, как волны 2–10 построят остальные пять подразделов. Следствие: документ делится на две части, и обе обязательны.

1. **Что уже отгружено — ДОКУМЕНТИРУЕТСЯ, а не переоткрывается.** Вкладки подразделов, строка воркера, две колонки состояния, пустые состояния пяти оболочек и CSS-блок `[data-subtabs]`/`.subtab` уже в `master`. Они здесь описаны как **де-факто контракт**, которому обязаны следовать оставшиеся пять подразделов. Переизобретать их запрещено: расхождение между отгруженным воркером и будущей очередью читалось бы как два разных механизма.
2. **Что ещё предстоит — КОНТРАКТУЕТСЯ.** «Очередь», «Логи», «Пользователи», «Обзор», «Платежи», полоса имперсонации и запреты под чужой личностью строятся впервые, и именно ими этот документ управляет.

**ДИЗАЙН-СИСТЕМА СУЩЕСТВУЕТ И НЕ ПРИНАДЛЕЖИТ ЭТОЙ ФАЗЕ.** Её завели Фазы 1–5: токены `app/static/css/app.css:24-95`, тринадцать макросов `app/templates/components/`, примитивы строки `[data-rowhead]` / `[data-row]` / `[data-grow]` / `[data-cell-label]`. **Ни один токен ниже не выдуман: каждый прочитан в `app.css` в этой сессии, с номером строки.** Там, где фаза вводит НОВОЕ, это помечено словом **НОВОЕ** явно — таких мест ровно три, и все три перечислены в `## Новое, чего в системе не было`.

## Spacing Scale

Проект живёт на ритме, вынесенном Фазой 1 из частотной таблицы 490 инлайн-стилей макета; он **не выровнен по сетке 4** и выровнен быть не может в границах этой фазы — те же значения держат 26 страниц. Сетка-4 обязательна для всего, что фаза **добавляет**.

| Token | Value | Usage в фазе |
|-------|-------|--------------|
| xs | 4px | `[data-subtabs]` gap и `margin-bottom` (`app.css:885-886`); `.chip` gap (`:1768`); `.empty__action` margin (`:766`) |
| sm | 8px | `[data-row]` row-gap на ≤860px (`:483`); `.chip-set` gap (`:1764`); `.chip-bar` row-gap (`:1814`) |
| md | 16px | `.btn` горизонтальный padding (`:681`); `[data-body]` боковой padding на ≤860px (`:478`); `.chip-bar` column-gap (`:1814`); `[data-pager]` margin-top (`:1524`) |
| lg | 24px | `[data-side]` вертикальный padding и gap (`:507-518`) |
| xl | 32px | `[data-body]` боковой padding на широкой ширине (`:675`) |
| 2xl | 48px | `.empty` вертикальный padding (`:763`) — пустые состояния всех шести подразделов |
| 3xl | 64px | **В фазе не применяется** |
| **touch-row** | **36px** | **Минимальная высота управляющего элемента ВНУТРИ строки.** Значение взято у `[data-group-row] .btn { min-height: 36px }` и `[data-group-row] .toggle { min-height: 36px }` (`app.css:2126-2127`) — единственного отгруженного прецедента действия в строке списка. См. `## Mobile Contract`, M3 |
| **touch-chip** | **44px** | `.chip { height: 44px }` (`app.css:1769`) — фильтры S4/S5/S7 получают полноразмерную нажимаемую цель **бесплатно**, потому что примитив уже такой |

**Exceptions — унаследованный ритм (не кратны 4, менять запрещено):**

| Value | Где | Почему остаётся |
|-------|-----|-----------------|
| 22px | `[data-stack]` gap — вертикальный ритм между блоками подраздела (`app.css:1410`) | Общий ритм всех разделов проекта |
| 18px / 20px | `.card__body` padding (`:744`) | Компонент `card`, общий |
| 15px / 20px | `.card__head` padding (`:738-741`) | Там же |
| 14px / 20px | `[data-row]` gap и padding; `[data-rowhead]` gap и padding (`:852-864`) | Примитив строки всех списков проекта |
| 13px | `[data-metrics]` gap (`:1176`) | Сетка плиток; её держат дашборд Фазы 4 и карточка пользователя |
| 11px / 14px | `.alert` padding (`:821`) | Компонент `alert` |
| 12px / 14px | `.chip-bar` padding (`:1815`) | Полоса чипсов Фазы 4 |
| 9px | `.btn` вертикальный padding (`:681`); `.cell` gap (`:868`) | Дословно из макета |
| 10px | `.empty` gap (`:763`); `[data-metric-line]` margin-top (`:1178`) | Ритм Фазы 1 |
| 90px | `[data-body]` нижний резерв на ≤860px (`:478`) | Резерв под фиксированную панель `[data-tabs]` |

**⚠️ ДВА ЗНАЧЕНИЯ, КОТОРЫЕ ВВЕЛА САМА ФАЗА 6 В ВОЛНЕ 1, И ОНИ НЕ КРАТНЫ 4. Названы здесь прямо, а не спрятаны:**

| Value | Где | Решение |
|-------|-----|---------|
| **3px** | `[data-subtabs] { padding: 3px }` (`app.css:886`) | **Остаётся.** Это внутренняя рамка полосы-подложки вокруг вкладок высотой ~35px; 4px раздули бы полосу до высоты, при которой она спорит с шапкой раздела. Значение однократное и в другие места не расходится |
| **13px** | `.subtab { padding: 8px 13px }` (`app.css:890`) | **Остаётся.** 13px — уже действующий горизонтальный ритм проекта: `.field__input { padding: 12px 13px }` (`:733`), `[data-rowhead] { padding: 13px 20px }` (`:855`). Выровняв вкладку по 12 или 16, фаза завела бы **второй** горизонтальный ритм рядом с первым — расхождение дороже, чем отступление от сетки-4 |

**Правило для волн 2–10:** ни одно НОВОЕ значение отступа, введённое оставшимися планами, не имеет права быть некратным 4. Два исключения выше закрыты и не расширяются.

## Typography

**НА ПОВЕРХНОСТЯХ ФАЗЫ: 4 рабочих кегля + 3 унаследованных = 7 кеглей; 2 структурных веса + 1 из общих компонентов = 3 веса. Счёт назван здесь, пересчитывать не нужно.**

Разделение на «рабочую шкалу» и «унаследованные токены» сделано по прямой рекомендации чекера фазы 5 (Dimension 4 FLAG). **Фаза не заводит и не переопределяет ни одного кегля и ни одного веса** — все семь и все три принадлежат Фазе 1 и общим компонентам.

**Рабочая шкала — четыре роли:**

| Role | Size | Weight | Line Height | Где в фазе |
|------|------|--------|-------------|------------|
| **Display** | 32px (`--fs-h3`) | 600 | 1.1 | `[data-metric-value]` (`app.css:1180-1184`), `letter-spacing:-.03em`, `font-variant-numeric: tabular-nums`. **Только четыре плитки «Обзора» (S6). Больше нигде в админке крупного числа нет** |
| **Heading** | 15px (`--fs-xl`) | 600 | 1.3 | `.card__title` (`:742`) — заголовки блоков: «Инциденты», «Инфраструктура», «Воркеры аккаунтов», «Журнал платежей», «Очередь по каналам» |
| **Body** | 13px (`--fs-md`) | 400 | 1.5 | `.cell` (`:868`), `.alert` (`:820-822`), `.card__subtitle` (`:743`), `.empty__hint` (`:768`), `[data-longtext]` (`:1155`, при 1.6). Кнопка — **тот же кегль при весе 600** (`:681`) |
| **Label (mono)** | 11px (`--fs-xs`) | 400 | 1.3 | `.mono` (`:810`), `.badge` (`:750`), `.cell--mono` (`:871`), `[data-metric-delta]` (`:1191`) — все подписи моношрифтом, включая время инцидента и глубину очереди |

**Унаследованные токены, которые фаза ЧИТАЕТ, но не объявляет:**

| Token | Size | Где в фазе | Кем объявлен |
|-------|------|------------|--------------|
| `--fs-2xs` | 10px | `[data-cell-label]` — подписи колонок, выезжающие на ≤860px (`:1529-1535`); `[data-rowhead]` (`:856`); `.badge--mono` (`:753`); `.field__label` (`:713`) | Фаза 1, `app.css:77` |
| `--fs-sm` | 12px | `.subtab` (`:891`) — **единственный потребитель этого кегля в фазе**; `.field__hint` (`:740`) | Фаза 1, `app.css:79` |
| `--fs-lg` | 14px | `.empty__title` (`:767`) — заголовки пустых состояний всех шести подразделов; `.chip` (`:1773`) — подписи фильтров; `.field__input` (`:735`) — поле поиска | Фаза 1, `app.css:81` |

**Weights — два структурных:** 400 (текст, все моношрифтовые подписи, содержимое ячеек) и 600 (заголовки блоков, числа плиток, кнопки).
**Exception:** 500 приходит из двух общих компонентов Фазы 1 — `.badge` (`app.css:750`) и `.btn--ghost` (`:696`). Фаза их не переопределяет и не имеет права переопределять.

**ПРАВИЛО КЕГЛЯ, ОБЯЗАТЕЛЬНОЕ К СОБЛЮДЕНИЮ: Display существует РОВНО В ЧЕТЫРЁХ местах фазы, и все четыре — плитки «Обзора».** Ни глубина очереди, ни число залипших платежей, ни MRR в подразделе «Платежи», ни счётчик «N из M» над списком пользователей Display **не получают**. Причина названа прямо: пятый и шестой крупный элемент отменяют первые четыре — если крупно всё, не крупно ничего, и администратор в аварии перестаёт видеть, какое из чисел главное. MRR на S7 печатается `[data-metric-value]` **только если** плитка стоит на «Обзоре» (D-37); в самом подразделе «Платежи» те же две величины идут `.card__subtitle` и `mono`.

⚠️ **Макет держит число плитки в 28px (`design/…unpacked.html:1046`). Фаза берёт 32px** — Фаза 1 нормализовала дробные и промежуточные кегли макета в целые ступени токенов (сознательное допущение A5, `app.css:74-76`), и `[data-metric-value]` уже отгружен на `--fs-h3`. Возврат к 28px завёл бы восьмой кегль ради одного экрана.

**Accent reserved for — ЗАКРЫТЫЙ ПЕРЕЧЕНЬ, ЧЕТЫРЕ ПОЗИЦИИ НА ВСЮ АДМИН-ПАНЕЛЬ:**

1. **Заливка кнопки `.btn--primary`** (`app.css:691`) — на поверхностях фазы это ровно **одна** кнопка: «Найти» в панели фильтров «Пользователей» (S5). Все прочие действия админки — `.btn--ghost` (навигация, «Обновить» в «Логах») либо `.btn--danger` (перезапуск, снятие задачи).
2. **Выбранный чипс фильтра** — `.chip--on { border-color: var(--accent); background: color-mix(in oklab, var(--accent) 14%, transparent) }` (`:1786-1789`). Применяется на S4 (уровень, окно), S5 (доступ, состояние), S7 (статус, период).
3. **Ссылка «куда чинить» в строке инцидента** — наследует `--accent-link` от `a` (S6, D-48).
4. **Ссылка из строки воркера в «Логи» с фильтром** — там же (S2, D-10).

**⚠️ АКТИВНАЯ ВКЛАДКА ПОДРАЗДЕЛА АКЦЕНТА НЕ ПОЛУЧАЕТ, И ЭТО РЕШЕНИЕ, А НЕ УПУЩЕНИЕ.** `.subtab[data-subtab-active] { background: #15151d; color: var(--text) }` (`app.css:899`) — приподнятый фон и яркий текст, тот же приём, что у активного нижнего таба шелла. Причина выписана в самом `app.css`: две полосы вкладок на одной странице обязаны отмечать активное одинаково, иначе читаются как разные механизмы. Покрасив активную вкладку акцентом, фаза сделала бы её пятым носителем акцента и **самым заметным элементом экрана** — притом что она сообщает «где ты», а не «что нажать».

**⚠️ ЗНАЧЕНИЕ `#15151d` — ЕДИНСТВЕННЫЙ ЗАХАРДКОЖЕННЫЙ ЦВЕТ, ВВЕДЁННЫЙ ФАЗОЙ.** Он взят из отгруженного `.tab-item[aria-current]` шелла, у которого токена нет. Правило файла («новых захардкоженных значений здесь нет», `app.css:696-700`) отступает здесь ровно потому, что альтернатива — завести токен под цвет, у которого уже есть один непоименованный носитель, и получить два имени одного значения. Расширять это исключение волнам 2–10 **запрещено**.

**Семантика статусов — фиксированная, из общих токенов. Действует на всех поверхностях фазы одинаково:**

| Состояние | Токен | Компонент | Где |
|-----------|-------|-----------|-----|
| Воркер работает | `--ok` | `badge('в работе', 'success')` | S1, S2 |
| Воркер простаивает (**норма**) | `--text-secondary` | `badge('простаивает', 'neutral')` | S1, S2 |
| Воркер отключён (**отказ**) | `--danger` | `badge('отключён', 'danger')` | S1, S2 |

- **ЧИСЛА НЕ КОПИРУЮТСЯ В КОПИРАЙТ.** Ни `20` (потолок инцидентов), ни `200` (потолок логов и платежей), ни `50` (страница пользователей), ни `90` (порог свежести heartbeat), ни `0.30` / `60` / `20` (порог всплеска, D-51) не выписываются литералом. Каждое живёт в **одной** константе и приезжает подстановкой. Прецедент дословный — `app/pages/billing.py:88-91`.
- **ПОТОЛОК НАЗЫВАЕТ СЕБЯ.** Молча усечённый перечень читается как «больше ничего нет» — то есть как ответ на вопрос, ради которого администратор в подраздел и пришёл. Действует на S3, S4, S6, S7.
- **ОТСУТСТВИЕ ВЕЛИЧИНЫ НАЗЫВАЕТ ПРИЧИНУ.** `mono('—')` без `title` запрещён там, где прочерк может быть прочитан как отказ: «в пуле app» вместо прочерка у TG-строки, «неизвестно» вместо «отключён» при мёртвом Redis.
- **«НЕИЗВЕСТНО» НЕ РАВНО «ОТКЛЮЧЁН».** Пустое состояние наблюдателя означает сломанный **наблюдатель**, а не сломанный воркер: показав отказ, подраздел отправил бы администратора чинить исправное. Правило уже отгружено в `worker_row.html` и распространяется на все четыре источника операционного состояния.
- **НЕДОСТУПНОСТЬ ВНЕШНЕГО ИСТОЧНИКА — ИМЕНОВАННАЯ ОШИБКА, А НЕ ПУСТОТА.** Loki, Redis и Docker деградируют в плашку с причиной и командой восстановления, **никогда** в 500 и **никогда** в пустой список.
- **ТЕКСТ СТОРОННЕГО ИСКЛЮЧЕНИЯ НА ЭКРАН НЕ ВЫХОДИТ.** Отказ Docker SDK и отказ HTTP-клиента журнала уходят в structlog именованным ключом; на экран — одна из фиксированных строк выше.
- **УПРАВЛЯЮЩИЙ ЭЛЕМЕНТ, УПИРАЮЩИЙСЯ В БЕССМЫСЛИЦУ, НЕ РИСУЕТСЯ ВОВСЕ**, а его место занимает подпись с причиной. Действует на «Остановить воркер», «Очистить очередь», «Выдать N дней».
- **ОДНО СОСТОЯНИЕ — ОДНО СЛОВО У ПОЛЬЗОВАТЕЛЯ И У АДМИНИСТРАТОРА.** Статусы платежей и состояния доступа берутся из 05.1-UI-SPEC дословно; вторая пара слов про то же состояние запрещена.
- **ДАННЫХ-ЗАГЛУШЕК МАКЕТА НЕТ НИ В ОДНОМ ПОДРАЗДЕЛЕ.** Число из макета, дожившее до прода, читается администратором как **измеренное**, и в аварии он примет решение по нарисованной цифре. Правило уже исполнено волной 1 и распространяется на волны 2–10.

## Mobile Contract

**375px — КРИТЕРИЙ ПРИЁМКИ ФАЗЫ (критерий 5: «все подразделы админ-панели пригодны к использованию на мобильных ширинах»), а не примечание.**

Браузерного харнесса в проекте нет (`playwright` / `selenium` отсутствуют в `pyproject.toml`). Утверждения ниже доказываются **арифметикой по CSS**; последнее — ручной приёмкой с числовыми порогами.

**Расчётное полотно:** 375px viewport − `[data-body]` боковой padding 16×2 (`app.css:478`) = **343px** содержимого. Внутри карточки: −`.card__body` padding 20×2 (`:744`) = **303px**.

| ID | Утверждение | Как измеряется | Статус |
|----|-------------|----------------|--------|
| **M1** | **Полоса шести вкладок не прокручивается и не обрезается** | `[data-subtabs] { flex-wrap: wrap }` (`app.css:884`). Ширины подписей при `.subtab` 12px + padding 13×2 + gap 4: `Обзор` ≈ 66px, `Пользователи` ≈ 116px, `Воркеры` ≈ 79px, `Очередь` ≈ 79px, `Логи` ≈ 60px, `Платежи` ≈ 79px.
