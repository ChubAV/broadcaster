<objective>
Трассирующий срез фазы: админ-панель становится шестью настоящими маршрутами с
вкладками, и ОДИН подраздел — «Воркеры» — доводится до конца через все слои, которые
фаза будет трогать: страничный обработчик → новый сервис чтения Redis → шаблон и
включение строки → стили → тест с подменённым клиентом.

Purpose: архитектура фазы содержит три несущих решения, каждое из которых дороже
исправить после десяти планов, чем после одного. Первое — подраздел есть МАРШРУТ, а не
состояние на одном экране (D-01): проверяется тем, что вкладки работают при выключенном
JS. Второе — живое состояние берётся из Redis, а Docker SDK при рендере не зовётся
(D-07): проверяется разбором исходника, а не наблюдением. Третье — новый сервис обязан
иметь ленивую ИМЕНОВАННУЮ точку получения клиента, иначе его нечем подменить в суите,
которая идёт на SQLite без внешних служб. Все три проверяются здесь, на одной строке
одного подраздела, до того как от них начнут зависеть двенадцать остальных планов.

Заодно план закрывает D-05: экраны справочника групп сносятся вместе с переписыванием
того же файла, а не отдельным заходом, и вердикт по ADMIN-02 вносится ЗДЕСЬ ЖЕ — снос
поверхности без вердикта делает «отменено» неотличимым от «потеряно».

Output: шесть достижимых подразделов, работающий подраздел «Воркеры» на живых данных,
`app/services/ops_state.py` как публичная точка чтения оперативного состояния, снесённый
справочник групп и записанный вердикт ADMIN-02.
</objective>

    Предикат свежести сравнивает ВОЗРАСТ, а не наличие: значение heartbeat — эпоха в
    миллисекундах у обоих каналов, и признак истинен, когда возраст неотрицателен и не
    превышает порога. Обе границы несущие. Верхняя — потому что WA-воркер пишет ключ БЕЗ
    срока жизни и удаляет его только при штатном завершении: убитый жёстко, он оставляет
    ключ навсегда, и проверка существования показывала бы мёртвый воркер живым бессрочно —
    именно в аварии, ради которой подраздел открывают. Нижняя — потому что heartbeat из
    будущего при расхождении часов иначе читался бы как «только что».

    Объявить функцию сводки живости: на вход список идентификаторов WA-аккаунтов и список
    MAX-аккаунтов, на выход словарь «идентификатор → {глубина очереди, состояние воркера}».
    Все обращения складываются в ОДИН pipeline: подраздел обновляется опросом, и запрос на
    каждый ключ умножился бы на число строк и на число тиков.

    Состояний ровно три плюс неизвестность. «В работе» — heartbeat свеж. «Отключён» —
    heartbeat несвеж И очередь непуста. «Простаивает» — heartbeat несвеж И очередь пуста;
    это ШТАТНОЕ состояние, а не отказ: воркер самоубивается через 300 секунд простоя, а
    менеджер контейнеров поднимает его только при непустой очереди. «Неизвестно» —
    Redis недоступен; отдавать в этом случае «отключён» значило бы сообщить об аварии
    воркеров, когда сломан наблюдатель.

    Ключи именовать по фактическому инвентарю (`06-RESEARCH.md` § Redis Key Inventory):
    очередь и heartbeat каждого канала со своим префиксом. Ключ конечной точки контейнера
    не читать — heartbeat отвечает на тот же вопрос точнее.
