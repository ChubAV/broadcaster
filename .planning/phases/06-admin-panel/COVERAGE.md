# API Coverage — Phase 6 «Админ-панель»

> Full coverage by default. Opt-outs are explicit, reasoned decisions.

**Почему матрица вообще существует для этой фазы.** Детектор внешних интеграций вернул
`detected: false`, и это отрицание НЕНАДЁЖНО: его словарь триггеров английский, а предмет
фазы описан по-русски. По существу фаза читает три внешние поверхности — HTTP API источника
логов (новый клиент пишется этой фазой), SDK управления контейнерами (существующая
интеграция, новое место вызова) и клиент брокера (существующая интеграция, новый вид
доступа из веб-процесса). Матрица составлена по существу, а не по ответу детектора.

**Правило второй интеграции.** Docker SDK и брокер интегрированы прошлыми фазами. Их
возможности переопределяются здесь ЗАНОВО от полного покрытия, а не наследуют прежние
отказы: перенос прежних опт-аутов молча накопил бы асимметрию между поверхностями.

## Loki HTTP API (новая интеграция, план 06-08)

| capability | decision | reason |
|---|---|---|
| `GET /loki/api/v1/query_range` | INTEGRATE | |
| `GET /loki/api/v1/query` (мгновенный срез) | OPT-OUT | подраздел показывает ОКНО за выбранный период (D-29); мгновенный срез отвечает на другой вопрос и в интерфейсе места не имеет |
| `GET /loki/api/v1/labels` | OPT-OUT | перечень источников — замкнутый словарь на стороне сервера, санируемый вместе с прочими осями фильтра; динамический открыл бы множество значений и добавил второй поход в источник на каждый рендер |
| `GET /loki/api/v1/label/{name}/values` | OPT-OUT | та же причина; ⚠️ имя контейнера службы канала telegram генерируется сборкой (допущение A2) и уточняется человеческой приёмкой плана 06-14 правкой ОДНОЙ строки словаря, а не динамическим запросом |
| `GET /loki/api/v1/series` | OPT-OUT | не нужно: селектор строится из объявленного словаря источников, а не из перечисления существующих потоков |
| `GET /loki/api/v1/tail` (потоковое чтение) | OPT-OUT | обновление подраздела — кнопкой, без опроса и без потока (D-29); «живой лог» в строке воркера отвергнут отдельным решением (D-10) |
| `GET /loki/api/v1/index/stats` | OPT-OUT | не нужно: объём индекса — вопрос эксплуатации источника, а не операционного среза внутри продукта |
| `GET /loki/api/v1/index/volume` / `volume_range` | OPT-OUT | та же причина |
| `GET /loki/api/v1/patterns` | OPT-OUT | не нужно: подраздел показывает строки, а не выведенные шаблоны сообщений |
| метрические запросы языка (`rate`, `count_over_time`, …) | OPT-OUT | счёт ошибок за сутки считает МОДУЛЬ АНАЛИТИКИ из базы (D-40), а не логи: инциденты и плитки обязаны работать при неподнятом мониторинге (D-28, D-43) |
| `POST /loki/api/v1/push` | OPT-OUT | логи пишет сборщик из стандартного вывода контейнеров; приложение в источник не пишет и писать не должно |
| `GET /ready`, `GET /metrics`, `GET /config` | OPT-OUT | доступность определяется САМИМ запросом окна с таймаутом: отдельная проба удвоила бы сетевые походы и могла бы разойтись с результатом основного запроса |
| `GET /loki/api/v1/status/buildinfo` | OPT-OUT | не нужно: версия источника на поведение подраздела не влияет |
| API удаления записей | OPT-OUT | подраздел только читает; удаление логов — операция эксплуатации источника, и давать её из продукта опасно |
| заголовок арендатора (`X-Scope-OrgID`) | OPT-OUT | аутентификация у источника выключена конфигурацией проекта; заголовок был бы обещанием несуществующего разграничения |

## Docker SDK (существующая интеграция, новое место вызова — план 06-05)

| capability | decision | reason |
|---|---|---|
| `containers.get` + запуск контейнера | INTEGRATE | кнопка «Перезапустить» (D-11) — единственное обращение к Docker во всей фазе |
| `containers.stop` | OPT-OUT | «Остановить воркер» не даётся (D-11): остановка обещает контроль, которого нет — воркер уходит сам через 300 секунд простоя и возвращается через 15 секунд при появлении задачи |
| `containers.list` при рендере подраздела | OPT-OUT | прямо запрещено (D-07): контракт Фазы 1 остаётся в силе буквально; живость берётся из брокера, а недоступный демон иначе уронил бы подраздел в аварии |
| `container.logs` | OPT-OUT | логи мёртвого воркера через SDK недоступны — контейнер уже удалён уборкой; их читает источник логов (D-27) |
| `container.stats` (нагрузка, память) | OPT-OUT | величины макета без предмета: контейнер воркера живёт минутами, и наработка у него бессмысленна |
| `containers.run` (создание контейнера) | OPT-OUT | созданием контейнеров воркеров управляет планировщик по непустой очереди; второй производитель развёл бы одно правило по двум местам |
| `containers.remove` | OPT-OUT | уборкой завершённых контейнеров занимается существующая задача; из админки удаление не даётся |
| `exec_run` | OPT-OUT | выполнение произвольной команды в контейнере из веб-интерфейса — расширение поверхности атаки без предмета в требованиях |
| `images`, `networks`, `volumes` | OPT-OUT | не нужно: фаза не управляет образами, сетями и томами |
| `events` (поток событий демона) | OPT-OUT | требует долгоживущего соединения из веб-процесса; живость читается из брокера дешевле |

## Redis (существующая интеграция, новый вид доступа из веб-процесса — планы 06-01, 06-05, 06-07)

| capability | decision | reason |
|---|---|---|
| `GET` / `MGET` (значения живости) | INTEGRATE | признак живости воркеров аккаунтов (D-06) |
| `LLEN` (длина очередей) | INTEGRATE | глубина очередей всех трёх каналов (D-08, D-13, D-37) |
| `LRANGE` (страница очереди) | INTEGRATE | построчный список задач каналов WhatsApp и MAX (D-13, D-16) |
| `LREM` (снятие одной задачи) | INTEGRATE | снятие конкретной задачи (D-17), количество задаётся явно единицей |
| `pipeline` (конвейер) | INTEGRATE | подраздел обновляется опросом, и запрос на ключ умножился бы на число строк и тиков |
| `SETEX` (кэш вердикта) | OPT-OUT | кэш вердикта блокировки не заводится (D-31): чтение строки по первичному ключу дешевле поверхности инвалидации |
| `SMEMBERS` над множеством активных аккаунтов | OPT-OUT | перечень аккаунтов берётся из базы — он там полон, а множество в брокере отражает только аккаунты с непустой очередью |
| `BLPOP` / `LPOP` / `RPOP` | OPT-OUT | снимающее чтение отняло бы у пользователей оплаченные рассылки просто оттого, что администратор открыл страницу; это работа воркера, а не наблюдателя |
| `KEYS` / `SCAN` | OPT-OUT | перебор ключей на боевом брокере — известная операция с непредсказуемой ценой; ключи строятся по идентификаторам из базы |
| публикация и подписка | OPT-OUT | обновление подраздела — опрос (D-12); долгоживущее соединение из веб-процесса фаза не заводит |
| `DEL` над ключами живости и конечных точек | OPT-OUT | эти ключи пишут и снимают воркеры; вмешательство наблюдателя сделало бы признак живости недостоверным |
| чтение ключей результатов отправки | OPT-OUT | статуса «в работе» в подразделе нет (D-15); результаты обрабатывает существующая задача |
| чтение ключей конечных точек контейнеров | OPT-OUT | признак живости отвечает на тот же вопрос точнее и с известным сроком свежести |

## Внешние поверхности, которых фаза НЕ касается

- Платёжная система: фаза только ЧИТАЕТ журнал платежей из своей базы; ни одного вызова
  внешнего SDK не добавляется. Матрица покрытия платёжного API (`05-tarify/COVERAGE.md`)
  остаётся в силе без изменений.
- Протоколы отправки Telegram, WhatsApp и MAX: граница фазы объявлена явно и не двигается.
- Flower: остаётся внешним инструментом эксплуатации на тех же правах, что Prometheus и
  Grafana (D-13); знает один канал из трёх и поднят без аутентификации.
