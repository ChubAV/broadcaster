## `test_image_base_url_comes_from_app_settings` краснеет только в общем прогоне (найдено планом 06-04)

**Что наблюдается.** `tests/test_pages/test_ads_editor.py::test_image_base_url_comes_from_app_settings`
проходит в одиночку и целым файлом (36 тестов зелёные), но падает в прогоне
`tests/test_application tests/test_pages` и в полном `just test`.

**Почему это НЕ дефект плана 06-04.** Контрольный прогон того же среза с
`--ignore=tests/test_application/test_incidents.py` даёт тот же красный тест
(1 failed, 1085 passed). То есть падение воспроизводится БЕЗ единой строки,
написанной этим планом; связь с планом отсутствует, а не «не найдена».

**Признак.** Соседний тест на той же фикстуре
(`test_editor_s3_public_url_global_comes_from_app_settings`) в том же прогоне
зелёный — то есть ломается ПЕРВЫЙ рендер с подменёнными настройками, а не
контракт как таковой. Похоже на состояние, закешированное предыдущим тестом
процесса (глобал шаблонов либо `lru_cache` настроек), то есть на порядковую
зависимость суиты, а не на регрессию S3-контракта.

**Почему не чинится здесь.** Границы предмета: план 06-04 не трогает ни
объявления, ни рендер, ни настройки S3. Поиск теста-предшественника — отдельная
работа, и делать её внутри плана про инциденты значило бы менять чужой файл без
объявленного вердикта.

## `get_user_from_cookie` отвергает заблокированного без ветки `act` — стык для плана 06-12 (найдено планом 06-06)

**Что наблюдается.** `app/pages/common.py`, `get_user_from_cookie`:

```python
user = await db.get(User, payload["sub"])
if user and user.is_blocked:
    return None
```

Проверка безусловна: ветки на признак действующего лица (`act`) в ней нет.

**Почему это важно.** D-26 объявляет решением, что **вход администратора под
заблокированным пользователем разрешён** — и это именно тот случай, ради которого
имперсонация нужна («за что меня заблокировали»). Имперсонация ездит СТРАНИЧНЫМ
путём, то есть ровно через эту функцию. Пока ветки `act` здесь нет, D-26 на
страницах не исполнится: администратор, вошедший под заблокированным, будет
неотличим от невошедшего.

**Почему не чинится планом 06-06.** План 06-06 прямо запрещает трогать страничный
путь («сюда не лезть»), и правка чужой поверхности без объявленного вердикта
повторила бы дефект, от которого фаза уходит. Это не дефект 06-06 — это стык,
замеченный, пока он виден.

**Кому.** План **06-12** (имперсонация, волна 8). Там же лежит выпуск токена с
`act`, поэтому ветка ложится в тот же предмет.

**Побочный факт, полезный тому же плану.** Закрытость страничной формы покупки для
заблокированного сегодня есть ПОБОЧНЫЙ ЭФФЕКТ этой самой функции и нигде тестом не
закреплена. Правка функции в 06-12 может открыть форму молча — стоит закрепить
тестом в том же плане.
