## Spacing Scale

Раздел живёт на ритме, вынесенном Фазой 1 из частотной таблицы 490 инлайн-стилей макета. Он **не выровнен по сетке 4** и выровнен быть не может в границах этой фазы: те же значения держат 26 страниц проекта, и перебазирование — работа milestone, а не раздела.

Сетка-4, обязательная для всего, что фаза добавляет ИЛИ правит:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Зазор иконки и подписи внутри пилюли |
| sm | 8px | `[data-metric-line]` gap; зазор строки на мобильной ширине |
| md | 16px | `.btn` горизонтальный padding; `[data-body]` боковой padding на ≤860px |
| lg | 24px | Внутренний отступ карточки плана в макете (`padding:24px`) |
| xl | 32px | `--fs-h3` кегль цены (размер, не отступ) |
| 2xl | 48px | `.empty` вертикальный padding пустых состояний |
| 3xl | 64px | Не применяется в разделе |
| **touch** | **44px** | **Минимальная высота нажимаемого элемента оплаты — см. `## Mobile Contract`, M3** |

**Exceptions — унаследованный ритм Фазы 1 (значения не кратны 4, менять в этой фазе запрещено):**

| 9px | `[data-plan-limits]` gap, `.btn` вертикальный padding | Дословно из макета (`gap:9px`) |

## Typography

| Role | Size | Weight | Line Height | Где в разделе |
|------|------|--------|-------------|---------------|
| Display | 32px (`--fs-h3`) | 600 | 1.1 | `[data-metric-value]` — цена плана, число доступных сообщений, название текущего тарифа. `letter-spacing:-.03em`, `font-variant-numeric: tabular-nums` |
| Heading | 15px (`--fs-xl`) | 600 | 1.3 | `.card__title` (заголовки пяти блоков), `[data-plan-name]` (имя плана). `letter-spacing:-.015em` |
| Body | 13px (`--fs-md`) | 400 | 1.5 | Строки лимитов карточки, `.card__subtitle`, `.empty__hint`, подпись назначения платежа. Кнопки — тот же кегль при весе 600 |
| Label (mono) | 11px (`--fs-xs`) | 400 | 1.3 | `.mono` (все подписи моношрифтом), `.progress__label` (подпись метра), `.badge`. `letter-spacing:.06em`, гарнитура `--font-mono` |
| Micro-label (mono, upper) | 10px (`--fs-2xs`) | 400 | 1.3 | `[data-cell-label]` — подписи колонок, выезжающие на ≤860px; теги карточки «ВАШ ПЛАН» / «БЕЗ ЛИМИТОВ». `letter-spacing:.12em`, `text-transform:uppercase` |

**Weights — два структурных:** 400 (текст и все моношрифтовые подписи) и 600 (заголовки, имена планов, цена, кнопки).
**Exception:** 500 приходит из двух общих компонентов Фазы 1 — `.badge` и `.btn--ghost`. Раздел их не переопределяет и не имеет права переопределять.

**Правило кегля, обязательное к соблюдению:** в карточке плана крупный элемент **ровно один — цена**. Имя плана держит кегль заголовка (15px), а не Display: второй элемент того же размера отнял бы у цены роль. Правило выписано в докстринге `plan_card.html:41-42` и в CSS `app.css:1166-1168`.

## Color

Тема одна — тёмная (Фаза 1 D-10). Светлого варианта нет и не планируется.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg: #08080b` + `--surface: #0e0e14` | Фон документа и полотно всех пяти карточек раздела |
| Secondary (30%) | `--surface-side: #0b0b10`, `--surface-pill: #0f0f16`, `--surface-input: #12121a` | Сайдбар, нейтральные пилюли, дорожка прогресса, подложка панели вкладок. Границы — лестница от `--border-hair: #14141b` до `--border-dashed: #2e2e3a`; карточка носит `--border: #1a1a23` |
| Accent (10%) | `--accent: oklch(0.72 0.19 310)`, `--accent-cta: oklch(0.79 0.14 305)`, `--accent-link: oklch(0.78 0.16 310)` | См. закрытый перечень ниже |
| Destructive | `--danger: oklch(0.68 0.19 25)` | Единственное применение в разделе — бейдж «отклонён» у отменённого платежа. **Разрушительных действий в разделе нет вовсе** |

**Accent reserved for — закрытый перечень, четыре позиции:**

1. Рамка карточки ТЕКУЩЕГО тарифа — `[data-plans] .card--current { border-color: var(--accent) }` (`app.css:1164`).
2. Тег `ВАШ ПЛАН` — `mono(..., 'accent')` в `plan_card.html:44`.
3. Заливка шкалы метра — `.progress__bar { background: var(--accent) }`, все четыре оси и виджет баланса.
4. Заливка кнопки оплаты — `.btn--primary { background: var(--accent-cta) }` на трёх формах раздела (`plan_card.html:74`, `balance.html:98`, `balance.html:157`).

**Чем акцент НЕ является:** тег `БЕЗ ЛИМИТОВ` у Pro красится в `--ok`, а не в акцент — тег текущего плана важнее самого щедрого, и человек ищет глазами свой (`plan_card.html:38,44`). Ссылки раздела, границы, подписи и моношрифтовые метки акцента не получают.

**Семантика статусов — фиксированная, из общих токенов:**

| Состояние | Токен | Где |
|-----------|-------|-----|
| `succeeded` → «проведён» | `--ok` (`badge--success`) | Строка платежа |
| `canceled` → «отклонён» | `--danger` (`badge--danger`) | Строка платежа |
| `pending` → «в обработке» | `--text-secondary` (`badge--neutral`) | Строка платежа |
| Срок подписки истёк | `--warn` (`badge--warning`, `mono --warn`) | Блок 1 |
| Потолок списка сработал | `--warn` (`mono --warn`) | Блок 5 |

**Прохибиция цвета (закреплена планом 05-05, судится ui-auditor'ом):** превышение лимита по оси **не красится тревожным цветом**. Шкала встаёт на 100, подпись называет настоящие числа («20 / 15»), вариант метра остаётся `accent`. Фаза ничего не запрещает (D-08) — красный метр обещал бы запрет, которого не существует. Правило выписано в `usage_meters.html:20-22`.

| **Overflow state** — потолок списка | `Показаны последние {200} платежей из {всего}` |
| Виджет сайдбара | `Баланс сообщений` + `{used} / {limit}` (или `∞`) + `ТАРИФЫ И ПОПОЛНЕНИЕ →` |
| **Destructive confirmation** | **Отсутствует — разрушительных действий в разделе нет.** Оплата не разрушительна и панели подтверждения не получает: платёж создаётся на стороне ЮKassa, а не списывается формой |

**Правила формулировок, обязательные к соблюдению:**

- **Одно состояние — одно слово у пользователя и у администратора.** `PAY_LABELS` взяты из макета админки (строки 2040-2050), чтобы Фаза 6 назвала то же самое так же (D-14, D-16).
- **Неизвестный статус печатается как есть** моношрифтом, а не прячется: спрятанное состояние платежа читается как «платежа не было» (`payment_row.html:61-63`).
- **Потолок называет себя.** Молча укороченный журнал денег читается как «других платежей не было» (D-17).
- **Виджет не подписывает себя величиной, которой не показывает.** Он рисует баланс сообщений и подписан «Баланс сообщений», а не тарифом — прежняя подпись врала (D-22, прохибиция 05-05).
- **Истечение срока формулируется как факт, а не как отключение** (D-07): «ничего не отключено».
- **Идентификатор `yookassa_payment_id` не печатается нигде** — ни значением, ни атрибутом, ни комментарием. Это ключ подделки уведомления; запрет держит `test_the_screen_never_prints_the_yookassa_payment_id`.

## Component Contracts

Четыре поверхности несут семантику состояний, которая **уже существует в коде и подлежит фиксации, а не пересмотру**.

### C1 — Карточка плана (`plan_card.html`)

| Свойство | Контракт |
|----------|----------|
| Количество | Ровно три (`free`, `basic`, `pro`) из `Settings.parsed_plan_limits`; список приходит готовым из обработчика, свойство разбора конфига из Jinja не зовётся |
| Анатомия | Имя + тег → цена + `/ мес` → четыре строки «подпись слева, значение моношрифтом справа» → CTA внизу |
| Порядок строк лимитов | Только `plan_axis_order`; вторая копия подписей в разметке запрещена |
| Выделение текущего | `card--current` → рамка `--accent`. Модификатор, а не форк макроса `card` |
| Тег | `ВАШ ПЛАН` (акцент) важнее `БЕЗ ЛИМИТОВ` (`--ok`); одновременно не рисуются |
| Безлимит | `∞`, если значение оси `null`. **Ни нулём, ни большим числом** |
| Free | Формы не получает — платёж на `0.00` ЮKassa отвергнет; вместо кнопки подпись `Текущий на старте` |
| `payments_enabled=false` | Гаснет **кнопка, а не витрина** (D-21): карточки и метры видны, на месте кнопки — подпись про администратора |
| Чего в карточке нет | Ни процентов, ни шкал. Карточка показывает, что тариф **даёт**; сколько израсходовано — дело метров |
| Форма | `<form method="post" action="/billing/subscribe">` с единственным скрытым полем `plan`. Цену читает сервер по идентификатору. Без JS работает полностью |

### C2 — Метр оси (`usage_meters.html`)

| Свойство | Контракт |
|----------|----------|
| Количество и порядок | Четыре, порядок задаёт `AXIS_ORDER = ('ads','groups','sends','accounts')`. Разметка порядок не пересобирает |
| Ось с лимитом | `progress(percent, label='{Ось} — {used} / {limit}')`, вариант `accent` |
| Безлимитная ось | **Шкалы нет вовсе.** Только `{Ось} — {used} / ∞` + `без ограничений`. Залитая шкала сообщила бы «израсходовано всё» там, где израсходовать нельзя |
| Деление | Не выполняется **ни разу** — ни в шаблоне, ни в модуле. Процент приезжает уже клампованным 0..100 |
| Превышение | Шкала на 100, подпись — настоящие числа, тревожного варианта нет (см. `## Color`) |
| Доступность | `role="progressbar"` + `aria-valuenow/min/max` приходят из макроса `progress` |

### C3 — Строка платежа (`payment_row.html`)

| Свойство | Контракт |
|----------|----------|
| Раскладка | Примитивы `data-rowhead` / `data-row` / `data-grow`. **Элементов `<table>` ноль** — запрет уровня инвентаризации по всем шаблонам проекта |
| Колонки | `Дата` · `Назначение` (grow) · `Сумма` · `Статус`, набор ширин `PAY_COLS` |
| Подписи колонок | `[data-cell-label]` обязателен у `Назначение`, `Сумма`, `Статус`. `Дата` освобождена: форматированная дата самоописательна |
| Шапка и подписи | Рисуются **одним списком** `PAY_COLUMNS`; расхождение увидит только тот, кто открыл раздел с телефона |
| Дата | Только `format_datetime_for_user(..., user)`. Свой формат даты запрещён |
| Сумма | Только `format_amount(payment.amount_value)` моношрифтом `bright`. Машинная строка (`"1490.00"`) превращается в подпись (`1 490 ₽`) **только на показе** |
| Назначение | Подписка → `{План} · первый платёж` / `{План} · продление`; первый платёж отличается картой `first_payment_at` без второго запроса. Пакет → `package_name` |
| Статус | Бейдж по `PAY_LABELS`; неизвестный — моношрифтом как есть |

## Mobile Contract

Критерий 4 ROADMAP («раздел тарифов пригоден к использованию на мобильных ширинах») — **единственный визуально открытый пункт фазы**: `05-VERIFICATION.md` держит его как `behavior_unverified`. Браузерного харнесса в проекте нет (`playwright` / `selenium` в `pyproject.toml` отсутствуют), а две существующие проверки — `test_billing_plans_grid_is_declared_folding` и `test_billing_plans_grid_rule_does_not_redefine_the_dashboard_grid` — читают CSS **как текст** и сами это признают в докстринге.

Контракт ниже **не повторяет, что пункт непроверяем**. Он разбивает его на измеримые части: четыре из пяти проверяются арифметикой по CSS без браузера, пятая остаётся ручной с числовыми порогами.

Расчётная ширина полотна: **375px** viewport − `[data-body]` боковые padding 16px×2 = **343px** контента.

| ID | Утверждение | Как измеряется | Статус |
|----|-------------|----------------|--------|
| **M1** | Три карточки планов складываются в одну колонку | `[data-plans]` объявлен `repeat(auto-fit, minmax(260px, 1fr))` с `gap:13px`. Две колонки требуют 260×2+13 = **533px > 343px** → auto-fit даёт ровно одну. Вывод арифметический, браузер не нужен | ✅ выполнено — `app.css:1159-1161`, покрыто двумя тестами |
| **M2** | Подписи колонок едут вместе со значениями | `[data-rowhead] { display:none !important }` и `[data-cell-label] { display:inline }` — оба внутри `@media (max-width:860px)`. Каждая ячейка `Назначение` / `Сумма` / `Статус` несёт `[data-cell-label]` | ✅ выполнено — `app.css:1479`, `:1489-1495`, `:487` |
| **M3** | **Кнопки оплаты нажимаемы** | `.btn` вычисляется в **33px**: 13px (`--fs-md` при `line-height:1`) + 9px×2 padding + 1px×2 border. Порог WCAG 2.5.8 (AA) — **24px**, целевой порог проекта — **44px**. `[data-plan-cta]` не имеет **ни одного** правила в `app.css` (grep даёт ноль). Измеряется грепом: правило `[data-plan-cta] .btn { min-height: 44px }` либо есть, либо нет | ⚠ **НЕ выполнено** — единственный найденный конкретный дефект мобильной пригодности раздела |
| **M4** | Ни один блок не требует горизонтальной прокрутки | Наборы колонок `PAY_COLS` (сумма минимумов **510px**) и `TX_COLS` (**612px**) шире полотна — и обязаны быть инертными ниже 861px. Инертность даёт `[data-row] { display:flex !important; flex-wrap:wrap !important }`, отменяющий `grid-template-columns`. Измеряется: ни одно правило раздела не возвращает `[data-row]` в grid на ≤860px и не объявляет фиксированной ширины > 343px | ✅ выполнено — `app.css:479-481`; проверять при каждой правке раздела |
| **M5** | Строка лимитов карточки не рвёт вёрстку длинной подписью | `[data-plan-limits] > div { flex-wrap: wrap }` — «Отправок в месяц» уходит на вторую строку, а не в прокрутку | ✅ выполнено — `app.css:1175-1179` |

**Ручная приёмка (backstop, порог числовой, не «на глаз»):**

> Открыть `/billing` при ширине **375px** с тремя планами, четырьмя осями и историей платежей длиннее экрана.
> **Пройдено, если:** (1) `document.documentElement.scrollWidth === 375`; (2) карточек планов в ряду ровно одна; (3) у каждой строки платежа видны подписи `Назначение` / `Сумма` / `Статус`; (4) каждая кнопка оплаты имеет `getBoundingClientRect().height >= 44`; (5) фиксированная панель `[data-tabs]` не перекрывает последний блок — нижний резерв `[data-body]` равен 90px и не меньше высоты панели.
> Пункты 1, 2, 3 и 5 предсказаны M1/M2/M4 арифметически — расхождение означает дефект CSS, а не дефект измерения. Пункт 4 сегодня **провалится** до закрытия M3.
