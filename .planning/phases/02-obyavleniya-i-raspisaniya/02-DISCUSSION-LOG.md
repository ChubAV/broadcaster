## Черновик и автосохранение

### Эффект статуса на отправку

| Option | Description | Selected |
|--------|-------------|----------|
| Черновик не отправляется | Планировщик пропускает расписания черновиков; цена — правка запроса в `app/worker/tasks.py` рядом с боевым пайплайном | ✓ |
| Статус только визуальный | Отличается только видом в списке; риск — бейдж «ЧЕРНОВИК» врёт, объявление уходит в группы | |
| Не отправляется + пауза расписаний | Плюс явное гашение `is_active` у расписаний при переводе в черновик | |

**User's choice:** Черновик не отправляется.

### Судьба `Ad.is_active`

| Option | Description | Selected |
|--------|-------------|----------|
| Заменить на status | Ввести `Ad.status`, мигрировать записи в published, `is_active` удалить | ✓ |
| Переиспользовать is_active | Без миграции; `is_active=false` трактуется как черновик, но семантика существующих записей меняется задним числом | |
| status рядом с is_active | Два похожих состояния, которые придётся объяснять в интерфейсе | |

**User's choice:** Заменить на status.
**Notes:** Проверено по коду — `Ad.is_active` не читается ни планировщиком, ни адаптерами отправки; это мёртвый флаг.

### Механика автосохранения

| Option | Description | Selected |
|--------|-------------|----------|
| Пауза ввода ~1.5–3 с | Штатный `hx-trigger="keyup changed delay:2s"`, без своего JS-таймера | ✓ |
| По потере фокуса поля | Минимум запросов, но длинный текст теряется при закрытии вкладки | |
| Пауза + по уходу со страницы | Надёжнее всего, но требует своего обработчика | |

**User's choice:** Пауза ввода ~1.5–3 с.

### Рождение объявления и публикация

| Option | Description | Selected |
|--------|-------------|----------|
| Черновик при первом вводе | `/ads/new` открывает пустой редактор; первое автосохранение создаёт запись и подменяет URL | ✓ |
| Черновик сразу при открытии | Проще код, но в списке копятся пустые черновики от каждого случайного клика | |

## Модель сохранения расписаний

### Момент сохранения

| Option | Description | Selected |
|--------|-------------|----------|
| Каждое сразу, отдельно | Своим HTMX-запросом; клиентского состояния, которое можно потерять, нет | ✓ |
| Всё одним «Сохранить» | Как в тексте макета, но конфликтует с автосохранением: текст сохраняется сам, расписания — нет | |
| Гибрид | Новое набирается клиентски и фиксируется «Готово», сохранённое правится сразу; два режима в одном компоненте | |

**User's choice:** Каждое сразу, отдельно.
**Notes:** Возможно потому, что по решению о черновике объявление к моменту настройки расписаний уже существует.

### Неполное расписание

| Option | Description | Selected |
|--------|-------------|----------|
| Сохранять неполным, но выключенным | `is_active=false`, тумблер доступен только при полном заполнении; ровно то, что показывают бейдж «ЧЕРНОВИК» и подсказка макета | ✓ |
| Сохранять только полное | Возвращает клиентское состояние, которое можно потерять | |
| Полное и сразу активное | Текущее поведение `/schedules/new`; теряется состояние «настраиваю, ещё не готово» | |

**User's choice:** Сохранять неполным, но выключенным.

### Деградация без JS

| Option | Description | Selected |
|--------|-------------|----------|
