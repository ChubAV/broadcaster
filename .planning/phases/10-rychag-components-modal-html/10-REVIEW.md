## Critical Issues

### CR-01: страж прошлого CR-01 конъюнкцию не выражает — снятие, применённое НЕ К ТОЙ заготовке, он принимает зелёным

**Файлы:** `tests/test_pages/test_shell.py:3403-3425` (`_lever_clearing_findings`),
`app/static/css/app.css:1013-1017`, `app/templates/includes/htmx_error_banner.html:109-111`

**Что не так.** Предикат построен двумя НЕЗАВИСИМЫМИ вхождениями по одному и
тому же телу метода:

```python
verb = f"setAttribute('{FAILURE_BANNER_HIDDEN_ATTR}'"
for banner_id in FAILURE_BANNER_IDS:
    if banner_id not in body:      # заготовка НАЗВАНА где-то в теле
        ...
    if verb not in body:           # глагол ЕСТЬ где-то в теле
        ...
```

Связи между «этой заготовкой» и «этим глаголом» нет ни одной. Воспроизведено
исполнением на боевом дереве (доктóренная копия рычага, снятие вырезано,
глагол применён к площадке приземления фокуса):

```
show() { … var ids = ['htmx-failure-server','htmx-failure-network'];
         document.getElementById('notice').setAttribute('hidden', ''); … }

_lever_clearing_findings(копия) -> ()          # ПРАВИЛО ЗЕЛЕНО
```

То есть дерево, на котором дефект `CR-01` седьмого круга ВЕРНУЛСЯ ЦЕЛИКОМ —
устаревшая плашка снова встаёт над кнопкой необратимого удаления и утверждает о
текущем действии неправду, — проходит единственный заведённый под него гейт без
единого красного.

**Почему это находка партии, а не наследство.** Утверждение о стережении
записано ПАРТИЕЙ и записано В ПРОДУКТОВЫЕ ФАЙЛЫ: `app.css:1016-1017` —
«Свойство стережётся правилом по ИСХОДНИКУ рычага в модуле шелла»;
`htmx_error_banner.html:109-111` — «закрыто оно снятием обеих заготовок в методе
открытия рычага». Замер показывает, что правило стережёт НЕ свойство, а два
независимых упоминания. И это тот же класс, который ЭТА ЖЕ партия назвала
находкой в соседнем плане: комментарий `test_walkthrough_anchors.py:255-257`
дословно объясняет, почему независимые подстрочные поиски конъюнкцию не
выражают, — и ради неё заводит отдельное правило. Урок применён в одном модуле
и не применён в другом в тот же день.

**Fix.** Сличать ПАРУ, а не два вхождения: разобрать тело до выражения снятия и
потребовать, чтобы перечень идентификаторов и глагол принадлежали ОДНОМУ
выражению, — тем же приёмом «оба признака на одном узле», который партия уже
написала в `test_walkthrough_anchors.py`:

```python
CLEARING_RE = re.compile(
    r"\[(?P<ids>[^\]]*)\]\s*\.forEach\((?P<cb>.*?setAttribute\(\s*'"
    + re.escape(FAILURE_BANNER_HIDDEN_ATTR) + r"'.*?)\)\s*;",
    re.DOTALL,
)

def _lever_clearing_findings(path: Path) -> tuple[str, ...]:
    body = _lever_show_body(_stylesheet_source(path))
    hit = CLEARING_RE.search(body)
    if hit is None:
        return ("тело `show()` не несёт ВЫРАЖЕНИЯ снятия: перечень заготовок и "
                "глагол снятия обязаны принадлежать ОДНОМУ выражению, иначе "
                "глагол, применённый к чужому узлу, читается как снятие",)
    named = hit.group("ids")
    return tuple(
        f"#{b}: заготовки нет в перечне ВЫРАЖЕНИЯ снятия тела `show()`"
        for b in FAILURE_BANNER_IDS if f"'{b}'" not in named
    )
```

и отрицательный контроль ровно на воспроизведённую выше форму — глагол на
чужом узле при названных заготовках обязан КРАСНЕТЬ.

### CR-02: строгое сличение простой части СНЯЛО с гейта цепи предков класс, который прежняя форма ловила

**Файл:** `tests/test_pages/test_shell.py:3841-3848` (`_selector_targets`)

**Что не так.** План 10-37 заменил подстрочное сличение (`ancestor in last`) на
строгое (`last in selectors`) — с верным основанием (`body` есть подстрока
`[data-body]`). Побочно строгое равенство перестало опознавать предка, к
селектору которого дописан ЛЮБОЙ квалификатор: класс, признак, псевдокласс.
Воспроизведено исполнением на боевой таблице:

```
_selector_targets("body.foo")             -> ()
_selector_targets(":root.dark")           -> ()
_selector_targets("[data-shell].collapsed") -> ()

app.css + "body.night { filter: blur(2px); }"    -> findings: 0
app.css + ":root.dark { filter: blur(2px); }"    -> findings: 0
app.css + "[data-body].wide { filter: blur(2px); }" -> findings: 0
```

`filter` на теле документа отнимает у подъёма окно ЦЕЛИКОМ — ровно тот исход,
ради которого `WR-07` и закрывался. Прежняя подстрочная форма все три случая
ЛОВИЛА (`"[data-shell]" in "[data-shell].collapsed"` истинно). То есть партия
закрыла один класс ложноотрицательных и открыла второй, БОЛЬШЕГО охвата: тема
оформления (`:root.dark`, `body.night`) — самая ходовая правка именно этих двух
селекторов, и `_ancestor_declarations` их не увидит.

**Почему это не названная граница.** Докстринг `_selector_targets:3826-3836`
называет ОДНУ границу — нечиненую половину `IN-02` про комбинаторы внутри
скобок. Цена перехода на равенство не названа НИ ОДНИМ словом, а
`test_the_failure_banner_ancestor_universe_is_addressed_by_stylesheet_selectors`
утверждает строгость только в ту сторону, где она помогает
(`[data-body]` не опознан как `body`), и не утверждает ничего в ту, где вредит.

**Fix.** Сличать ПРОСТУЮ ЧАСТЬ ПО ЕЁ ПЕРВОМУ КОМПОНЕНТУ, а не по всей строке —
квалификаторы сужают, но предка не меняют:

```python
_CSS_QUALIFIER_RE = re.compile(r"(?<=.)[.:\[#]")   # первый квалификатор ПОСЛЕ головы

def _simple_head(part: str) -> str:
    hit = _CSS_QUALIFIER_RE.search(part)
    return part[:hit.start()] if hit else part

# ...
    last = compound[-1]
    for ancestor, selectors in FAILURE_BANNER_ANCESTORS.items():
        if (last in selectors or _simple_head(last) in selectors) and ancestor not in hits:
            hits.append(ancestor)
```

и — обязательно — отрицательный контроль на КАЖДЫЙ из трёх воспроизведённых
выше случаев, иначе следующая правка сличения снимет их так же молча.

### WR-04: правило достижимости рычага не знает ребра `{% import … as … %}`

**Файл:** `tests/test_pages/test_shell.py:4511-4513`, `4667-4693`

Образец ребра подключения макроса покрывает ОДНУ из двух форм Jinja:

```python
TEMPLATE_MACRO_IMPORT_RE = re.compile(r"{%-?\s*from\s+[\"']([^\"']+)[\"']\s+import\s")
```

Вторая форма — `{% import "components/modal.html" as m %}` — рычаг в шелл
приводит ровно так же (`m.modal(...)`), и правилом не видна. Воспроизведено
исполнением на доктóренной копии `auth/forgot_password.html`:

```
from-import  -> findings: 1      # ловится
import-as    -> findings: 0      # НЕ ЛОВИТСЯ
include      -> findings: 1      # ловится
```

Антивакуумная половина (`macro_only` непусто) дыру не показывает: она зеленеет
от `components/alert.html`, приезжающего формой `from`. Замер комментария
(«246 подключений, ВСЕ несут имя строковым литералом») верен, но считался по
той же форме `from` — вторая форма в него не входила и потому «сегодня их ноль»
не измерено, а предположено.

**Fix.** Второй образец рядом с первым, с тем же захватом имени, и оба — в
кортеж рёбер:

```python
TEMPLATE_MACRO_IMPORT_RE = re.compile(
    r"{%-?\s*(?:from\s+[\"']([^\"']+)[\"']\s+import\s|import\s+[\"']([^\"']+)[\"']\s+as\s)"
)
```

(с разбором обеих групп) плюс параметризовать
`test_control_an_auth_template_that_imports_the_lever_reddens` по ТРЁМ родам
рёбер — сегодня он проверяет одно из трёх.

блоком. Замер по боевой таблице:

```
блок подъёма (10 строк объявлений):  len(raw) = 7487
raw[:2] == "/*"                       True     # кусок НАЧИНАЕТСЯ комментарием
raw.count("position: fixed")  = 2              # одно объявление + одно упоминание в прозе
raw.count("position: fixed;") = 1              # держится ОДНИМ символом «;»
```

Докстринг `:2895-2899` обещает «ИСХОДНЫЙ кусок… вместе с комментариями ВНУТРИ
блока»; на деле — вместе с комментариями ПЕРЕД блоком. Следствие не
теоретическое: `test_control_a_banner_lift_block_without_a_fixed_position_reddens`
опирается на `raw.count(dropped) == 1`, где `dropped == "position: fixed;"`, а
прозаический абзац этого же куска (`app.css:973-976`) величину уже дважды
УПОМИНАЕТ. Первая же правка прозы, поставившая точку с запятой внутрь обратных
кавычек, покрасит контроль текстом «снятие задело бы прозу комментария» — то
есть красным на прозе, а не на дефекте (класс `07-REVIEW.md IN-02`, `IN-01`
седьмого круга).

**Fix.** Либо вернуть `raw` к границам блока (`rule_start` вести от первого
непробельного символа прелюдии в `text`, а не от конца предыдущего правила),
либо назвать свойство в докстринге ДОСЛОВНО и перевести якорь контроля на
границу блока:

```python
prelude_start_real = prelude_start + (len(text[prelude_start:index])
                                      - len(text[prelude_start:index].lstrip()))
found.append((prelude, text[body_start:index], source[prelude_start_real:index + 1].strip()))
```

### WR-06: контроль правила конъюнкции не отличает сработавшую ветвь от соседней

**Файл:** `tests/test_templates/test_walkthrough_anchors.py:548-549`

```python
findings = dialog_role_findings(doctored)
assert len(findings) == 1, _report(findings)
assert "1.2" in findings[0], findings[0]
```

Фрагмент `1.2` несут ОБА текста отказа — и `ID_LEFT_THE_TAG`, и
`ROLE_LEFT_THE_TAG` (каждый называет несущий счёт шага 1.2). Проверено
исполнением: доктóривание, УБИРАЮЩЕЕ идентификатор вместо роли, даёт одну
находку, и `"1.2" in findings[0]` на ней ИСТИННО. То есть контроль,
объявленный доказательством ветви роли, зеленеет и на ветви идентификатора —
та же ошибка «сличение по словам, общим двум ветвям», которую партия УЖЕ
исправила в соседнем модуле, выбрав для `stacking-context-group` фрагмент,
которого нет в ветви слоя (`test_shell.py:4026-4029`).

**Fix.** Сличать по фрагменту, принадлежащему РОВНО ветви роли, и утверждать
отсутствие чужого:

```python
assert findings == [ROLE_LEFT_THE_TAG], _report(findings)
```

(и, поскольку ветвь идентификатора теперь не исполняется НИ ОДНИМ контролем, —
второй случай доктóривания на неё, зеркальный первому.)

### WR-07: контроль достижимости подменяет читателя, но состав наследников по-прежнему берётся с диска

**Файл:** `tests/test_pages/test_shell.py:4667-4693`, `4746-4793`

`_auth_shell_lever_findings(read=…)` передаёт подменённого читателя в
`_template_graph_from`, но `_auth_shell_heirs()` внутри той же функции читает
дерево НАПРЯМУЮ (`root.rglob`, `path.read_text`) и параметра не принимает.
Следствие: контроль умеет доктóрить только СУЩЕСТВУЮЩИЙ шаблон, и сценарий,
которым докстринг `_auth_shell_heirs` оправдывает чтение дерева вместо списка,
— «восьмой экран входа, добавленный без правки суиты» — исполнением НЕ
показан ни разу. Восьмой наследник, приводящий рычаг, доказывается сегодня
только прозой.

**Fix.** Пробросить `read` (и перечень имён) в `_auth_shell_heirs`, дав ему тот
же необязательный параметр, что у графа, и добавить случай контроля «новый
наследник корня несёт подключение рычага».

### WR-08: отказ «глагола нет» печатается по разу на заготовку, хотя проверка от заготовки не зависит

**Файл:** `tests/test_pages/test_shell.py:3403-3425`

Проверка `if verb not in body` стоит ВНУТРИ цикла по заготовкам, а предметом
имеет тело целиком. Воспроизведено исполнением (глагол заменён на
`removeAttribute`):

```
findings: 2 — оба текста РАЗЛИЧАЮТСЯ только именем заготовки,
              а сказанное в них одно и то же: «глагола в теле нет»
```

Докстринг `_banner_elevation_findings:2988-2995` в этом же модуле формулирует
противоположную доктрину дословно: «Низкий слой — расхождение НА БЛОК: блок один
на обе, и два одинаковых сообщения о нём сказали бы одно и то же дважды».
Здесь она нарушена, и контроли это закрепляют: они требуют РОВНО
`len(FAILURE_BANNER_IDS)` находок, то есть удвоение теперь стережётся.

**Fix.** Вынести проверку глагола из цикла и считать её расхождением НА ТЕЛО:

```python
if verb not in body:
    return (f"тело метода `{MODAL_OPEN_METHOD}()` не несёт глагола `{verb}` — "
            f"заготовки {', '.join(FAILURE_BANNER_IDS)} остаются поверх панели",)
```

с приведением ожиданий обоих контролей.

### IN-02: счётчики скобок и кавычек не знают строковых литералов JS

**Файлы:** `tests/test_pages/test_shell.py:3358-3369`,
`tests/test_templates/test_walkthrough_anchors.py:444-475`

`_lever_show_body` считает `{`/`}` без оглядки на строки и знаки экранирования;
`_modal_opening_tag` переключает состояние на любой кавычке вне кавычек. Символ
`}` или одиночный апостроф внутри строкового литерала тела `show()`
(`'{'`, `"it's"`) сдвинет границу разбора: первый вернёт кусок неизвестных
границ, второй поднимет «тег не замкнут» — проверено исполнением на синтетике
(`<div class="modal" … data-x=it's role="dialog">` → `TAG_NOT_CLOSED`).
Сегодня таких литералов в рычаге нет, обе ошибки латентны.

**Fix.** Назвать границу в докстрингах обоих разборщиков наравне с уже
названными, либо считать строки состоянием (кавычка + экранирование).
