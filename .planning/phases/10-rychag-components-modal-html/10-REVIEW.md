### CR-01: строчный комментарий с фигурной скобкой молча уводит границу тела метода — подстрочное правило снятия заготовок зеленеет на переехавшем снятии

**File:** `tests/test_pages/test_shell.py:3649-3746` (`_lever_show_body`; счёт
вложенности `:3726-3741`, вырезание строчного комментария `:3741`), потребитель —
`:3771-3830` (`_lever_clearing_findings`), контроль — `:4048-4055`
(`test_control_a_lever_that_keeps_a_stale_banner_reddens`, половина 2)

**Issue:**
Счёт фигурных скобок идёт по тексту, из которого строчные комментарии ЕЩЁ НЕ
вырезаны (`_JS_LINE_COMMENT_RE.sub` применяется к УЖЕ вырезанному куску, строка
`return _JS_LINE_COMMENT_RE.sub("", text[start + 1:pos])`). Одна незакрытая `{`
внутри `// …` в теле `show()` увеличивает глубину, разбор перешагивает
закрывающую скобку метода и ВБИРАЕТ соседний метод.

Воспроизведено исполнением (синтетика, не дерево):

```python
src = ('<div x-data="{\n  show() { // открываем { панель\n'
       '    this.open = true; },\n'
       "  hide() { this.open = false; "
       "['htmx-failure-server','htmx-failure-network'].forEach(function(i){"
       " var n=document.getElementById(i); if(n){ n.setAttribute('hidden',''); } });"
       ' }\n}">')
_lever_clearing_findings(path_of(src))   # → ()   ← ЗЕЛЕНО
```

Снятие заготовок здесь живёт ЦЕЛИКОМ в `hide()`, то есть воспроизведена дословно
мутация «снятие, перенесённое в закрытие», ради которой существует половина 2
отрицательного контроля. Правило её не видит.

Отягчающее: докстринг `_lever_show_body` утверждает —
«Сегодня таких скобок в теле нет, и контроль строчного комментария утверждает это
ПРЯМО, а не полагается на удачу». Замер этого утверждения не подтверждает:
`test_control_a_lever_that_hides_its_clearing_in_a_line_comment_reddens`
утверждает `"{" not in line_comment` про СОБСТВЕННУЮ синтетическую строку
комментария, а не про тело живого рычага. Свойство держится тем, что сегодня в
теле `show()` строчных комментариев со скобкой не набрано, — то есть расписанием,
а не формой, ровно как это уже случилось с окном 70.

Смягчающее (называется, чтобы следующий читатель не переоценил находку):
поведенческая конъюнкция закрыта соседом —
`test_the_lever_clears_both_failure_banners_by_execution`
(`tests/test_templates/test_components.py`) исполняет `show()` и на этой же
мутации КРАСНЕЕТ. Дефектен антивакуумный слой, а не оба слоя сразу. Но слой этот
объявлен неудаляемым и стерегущим переезд снятия в закрытие — и именно этого он
не делает.

**Fix:** либо вырезать строчный комментарий ДО счёта вложенности (отдельным
проходом по телу-кандидату), либо, если охват вырезания менять нельзя, завести
утверждение по ЖИВОМУ рычагу:

```python
_JS_LINE_COMMENT_RE = re.compile(r"(?<![:\w])//[^\n]*")

def _lever_show_body(source: str) -> str:
    text = _JS_BLOCK_COMMENT_RE.sub("", _without_comments(source))
    anchor = _MODAL_OPEN_METHOD_RE.search(text)
    ...
    # счёт ведётся по тексту, из которого строчные комментарии уже вырезаны;
    # ветвь строкового литерала остаётся — она сужает счёт, а не отменяет его
```

и добавить контроль-зубы: скобка, вписанная в строчный комментарий тела,
обязана оставить границы тела ПРЕЖНИМИ (сегодня она их сдвигает), а
`_lever_clearing_findings` на переехавшем в `hide()` снятии — отдать
`len(FAILURE_BANNER_IDS)` находок при ЛЮБОМ содержимом комментариев.

### WR-02: правило набираемости якорей различает АЛФАВИТ, а не выражение селектора

**File:** `tests/test_templates/test_walkthrough_anchors.py:493-520`

множества» и завести ОТДЕЛЬНОЕ основание для «часть выражения не есть простой
селектор», с контролем на `#sched-1 - the schedule card`.

```python
_declares_banner_id('<div data-id="htmx-failure-server">', 'htmx-failure-server')     # True
_declares_banner_id('<div hx-target-id="htmx-failure-server">', 'htmx-failure-server')# True
```

То есть ССЫЛКА на заготовку из соседнего шаблона будет объявлена вторым
ИСТОЧНИКОМ разметки, и гейт единственности источника покраснеет там, где второго
источника нет. Разделение «читатель заготовки не есть её источник» — предмет
`CR-01` седьмого круга и отдельного утверждения в новом контроле; здесь оно
обходится дефисным префиксом.

**Fix:**

```python
_BANNER_ID_ATTR_RE = r"""(?<![\w-])id\s*=\s*(?:"{bid}"|'{bid}'|{bid}(?![\w-]))"""
```

и третий случай в
`test_control_a_second_script_with_the_other_quote_reddens_the_single_source_gate`:
`data-id="…"` НЕ обязан попадать во множество владельцев.

### IN-01: вакуумное утверждение в `_xdata_with_clearing_in_a_line_comment`

**File:** `tests/test_templates/test_components.py:4436-4439`

**Issue:** `assert "\n" not in chunk.strip()` истинно ПО ПОСТРОЕНИЮ: `chunk`

**Fix:** снять либо перенести проверку в `_clearing_chunk` (там она была бы о

### IN-02: вакуумная половина сличения чисел в контроле прозы роадмапа

**File:** `tests/test_planning/test_state_progress_matches_roadmap.py:501-503`

### IN-03: требование «шапка называет якорь» ломается о якорь, набранный отдельной строкой в прозе

**File:** `tests/test_planning/test_deferred_items_are_idempotent.py:233-238`
