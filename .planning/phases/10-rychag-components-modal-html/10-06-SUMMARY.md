## Задача 1 — фрагментный маршрут

### Антивакуум ДОКАЗАН: строка БЫЛА и ИСЧЕЗЛА

Состояние читается ЗАПРОСОМ К БАЗЕ через фикстуру сессии, а не выводится из ответа
(ответ и есть предмет сличения). Дословно:

```
SELECT id BEFORE first = 1
SELECT id AFTER  first = None
```

То есть второй запрос — ДЕЙСТВИТЕЛЬНО ПОВТОР, а не вторая попытка первого.

### Оба множества идентификаторов — ДОСЛОВНО

```
url_first_two   = /schedules/1/delete
url_shifted     = /schedules/2/delete
schedule_id     = 1 | other_id = 2
status first/repeat/shifted = 200 200 200

first_ids       = ['#sched-count', 'sched-1', 'sched-del-1']
repeat_ids      = ['#sched-count', 'sched-1', 'sched-del-1']
shifted_ids     = ['#sched-count', 'sched-2', 'sched-del-2']

expected(sid)   = ['#sched-count', 'sched-1', 'sched-del-1']
expected(other) = ['#sched-count', 'sched-2', 'sched-del-2']
```

`repeat_ids == first_ids` — неотличимость держится. `shifted_ids != repeat_ids` при
ОДИНАКОВОМ статусе `200` у всех трёх — сличение множеств НЕ ТРИВИАЛЬНО и реагирует
именно на идентификатор, а не на смену ветки.

Тело ответа повтора дословно:

```html
<div id="sched-1" hx-swap-oob="delete"></div>
<div id="sched-del-1" hx-swap-oob="delete"></div>
<div hx-swap-oob="innerHTML:#sched-count">…<span class="mono mono--muted mono--upper">2 расписания</span></div>
```

### Три ожидаемых значения — ОТКУДА ВЗЯТЫ

`sched-1` и `sched-del-1` СОБРАНЫ ИЗ ИДЕНТИФИКАТОРА ПОСЕВА (`_expected_oob_ids(schedule_id)`),
а не выписаны литералами: литерал разошёлся бы с посевом при первом же изменении
последовательности идентификаторов.

⚠️ **Третье значение `#sched-count` — СТАТИЧЕСКИЙ СЕЛЕКТОР, и это измеренный факт разметки,
а не послабление.** Узел линейки счётчика адресует цель значением `hx-swap-oob="innerHTML:#sched-count"`
и собственного `id` не несёт вовсе (`app/templates/ads/partials/sched_delete_response.html:75`);
от идентификатора удаляемой строки он не зависит НИЧЕМ, поэтому «собирать его из посева» было бы
нечем, а разойтись с посевом он не может по построению. Названо, а не умолчано.

## Задача 2 — маршруты перехода

### Перечень изъятий ЦЕЛИКОМ: ключ → основание

Предикат включения, ДОСЛОВНО: **маршрут ОСТАЁТСЯ под правилом, если его действие УНИЧТОЖАЕТ
АДРЕСУЕМУЮ СТРОКУ, то есть второй запрос с тем же телом уже не имеет предмета. Маршрут
ИЗЫМАЕТСЯ, если повтор ЗАПУСКАЕТ ДЕЙСТВИЕ ЗАНОВО (постановка работы в очередь, перезапуск
процесса, смена личности) либо если адресуемая строка не уничтожается вовсе.**

| Ключ | Основание изъятия |
|---|---|
| `app/pages/history.py::history_retry` | повтор СТАВИТ ОТПРАВКУ В ОЧЕРЕДЬ ЗАНОВО, а не удаляет строку: запись журнала переживает запрос целиком. Второе нажатие в пределах окна удержания отвечает СВОИМ кодом исхода (`retry_busy`), и это записанный контракт защиты от второй необратимой отправки, а не расхождение |
| `app/pages/admin.py::admin_restart_worker` | повтор ПЕРЕЗАПУСКАЕТ КОНТЕЙНЕР ЗАНОВО: аккаунт, адресуемый путём, не уничтожается ничем, и два подтверждения означают два выполненных перезапуска, а не один и холостой путь |
| `app/pages/admin.py::admin_drop_task` | адресуемая ПУТЁМ строка — аккаунт — не уничтожается вовсе; снимается задача, названная ТЕЛОМ формы. | `app/pages/admin.py::admin_impersonate` | повтор МЕНЯЕТ ЛИЧНОСТЬ ЗАНОВО, ничего не уничтожая: после первого запроса клиент уже несёт cookie цели, и второй отвергается зависимостью запрета вложенного входа — другая ветка, а не тот же ответ |
