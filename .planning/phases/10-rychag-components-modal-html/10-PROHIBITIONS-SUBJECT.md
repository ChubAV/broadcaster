## Почему этот файл существует

Пункт 4 перечня Human Verification девятого круга (`10-VERIFICATION.md:828-836`) блокирует
закрытие фазы дословно так:

> **Тест:** по каждому запрету — предъявить принуждение (25 с `verification: test`) либо дать
> явное разрешение (14 с `verification: none`).
> **Ожидание:** ни один запрет не остаётся молча зелёным.
> **Почему человек:** регламент велит закрывать такие пункты fail-closed.

У пункта есть ЧИСЛО и нет ПРЕДМЕТА. Настоящий файл даёт предмет: по каждой из 39 записей —
дескриптор, итог и ИМЯ найденного правила либо прямое «правила с таким предметом в дереве нет».

## Как снят замер — разбором, а не чтением

Frontmatter каждого из 47 планов фазы разобран YAML-разбором, из него взят блок
`must_haves.prohibitions`, и записи посчитаны по РОДАМ. Числа ниже сняты прогоном, а не перенесены
из прозы плана.

**Роды объявлены отдельно и НЕ слиты.** Запись-словарь с полем `verification`, запись-словарь БЕЗ
этого поля и запись-строка (без словаря вовсе) считались тремя разными родами: слитый счёт скрыл
бы разницу между «дескриптор объявлен пустым» и «поля нет вовсе».

**Результат разделения — находка, и она называется:** записей без поля `verification` — **0**,
записей-строк — **0**. Все 239 записей блока запретов во всех 47 планах фазы несут словарь с полем
дескриптора. Различение оказалось пустым, и это сказано прямо, а не выдано за проделанную работу.

## Что здесь значит «принуждается»

Дескриптор `verification: test` есть ОБЪЯВЛЕНИЕ АВТОРА о том, чем запрет предполагается стеречь.
Это не ссылка на правило. Ниже у каждой записи с этим дескриптором предъявлено одно из трёх:

- **`принуждается`** — названо ИМЯ правила дерева `tests/`, которое падало бы при нарушении
  запрета целиком;
- **`принуждается частично`** — названо ИМЯ правила и НАЗВАНА половина запрета, которую оно не
  покрывает;
- **`не принуждается`** — правила с таким предметом в дереве не нашлось. Формулировка не
  смягчается: запись без имени правила есть запись `не принуждается`.

Записи с дескриптором `none` принуждения не имеют ПО ПОСТРОЕНИЮ — их предмет разбирается
отдельным разделом ниже.

## Чего этот файл НЕ делает

**Он не выносит вердикта.** Поля вердикта в шапке нет; `status: subject` объявляет файл предметом
решения. Вердикт фазы даёт `10-VERIFICATION.md`, и он остаётся `gaps_found`.

**Он не объявляет ни один запрет соблюдённым.** Итог `не принуждается` есть утверждение об
ОТСУТСТВИИ ПРАВИЛА, а не о нарушении запрета; итог `принуждается частично` есть утверждение о
правиле, а не о поведении исполнителя. Ни то, ни другое соблюдения не подтверждает и не опровергает.

**Он не заводит ни одного правила.** Заведение недостающих правил есть работа, объём которой и
решает владелец. Настоящий план `tests/` и `app/` не касается ни на строку.

**Он не двигает отметку требования и не правит исполненных планов.** `FORM-06` в
`.planning/REQUIREMENTS.md` остаётся неотмеченным, `10-VERIFICATION.md` не тронут, планы
`10-01`…`10-40` не правлены ни на символ — дескриптор, дописанный в исполненный план задним
числом, превратил бы обещание в принуждение росчерком пера.

**Он не выбирает ветвь.** Выбор между требованием принуждения у каждого запрета и явным разрешением
записью принадлежит владельцу и делается на блокирующем чекпойнте. Раздел ответа (заголовок второго
уровня) встанет в этот файл ПОСЛЕ ответа владельца и до настоящего раздела — ровно один раз, по
якорю, а не дописыванием в конец.
