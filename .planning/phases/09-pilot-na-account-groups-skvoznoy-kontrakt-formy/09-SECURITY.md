## Trust Boundaries

The 20 plans name 51 boundary phrasings; they consolidate to the following.

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| браузер → страничный/фрагментный слой FastAPI | `account_id` / `group_id` arrive as URL segments and form bodies on `toggle`, `delete`, `partial` — all untrusted | identifiers, `search`, cursor (`after_id`), checkbox state |
| cookie сессии → личность пользователя | `get_user_from_cookie` on every entry; the only active CSRF defence is `SameSite=Lax` | session identity |
| внешний мессенджер → `Group.name` | group names are not controlled by the application and are rendered inside swapped fragments | untrusted display strings |
| ответ сервера → заголовок `HX-Location` | navigation primitive assembled from an address carrying a user-supplied path segment | redirect target |
| ответ сервера → DOM / документ / консоль браузера | fragment-swap surface, out-of-band nodes, inline script | markup, out-of-band node ids |
| исходник шаблонов / модулей / стилей → сканер гейта | gate rules read project source; a rule with an empty offender set is a silent failure | source text, declared inventory constants |
| подпроцесс тестов → интерпретатор JS | `run_node_script` (`tests/conftest.py:384`) — test-only, never imported by `app/` | in-repo template literals only |
| человек / посевная команда → живая база разработчика | walkthrough seed stand written into a live local database | `UAT9-`-prefixed seed rows |
| артефакты планирования / верификации → следующие фазы | marks, verdicts and requirement states are the record future phases build on | requirement states, walkthrough marks |
| исполнитель → бухгалтерия требований | requirement state transitions and inventory counters must not move without a reproducible basis | state tables, checkboxes, ledger counters |
