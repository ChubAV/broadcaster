## Источник блока конфигурации

### Где физически живёт блок `<meta name="htmx-config">`?

| Option | Description | Selected |
|--------|-------------|----------|
| Общий include на два шелла | `app/templates/includes/htmx_config.html`, `{% include %}` в обоих `<head>`. Конфиг остаётся видимым глазами, расхождение копий невозможно по построению | ✓ |
| Два литеральных блока | Копия в каждом шелле — буквально как написано в FOUND-02; единство держится только тестом | |
| Python-константа через `tojson` | `HTMX_CONFIG` в `common.py` → глобал Jinja; порядок правил перестаёт быть виден в разметке | |

**User's choice:** Общий include на два шелла
**Notes:** Совпадает с доктриной проекта «один источник, не вторая копия» (D-13/D-14 Фазы 1).

### Чем тест утверждает каждую строку конфига?

| Option | Description | Selected |
|--------|-------------|----------|
| Разбор JSON из отрендеренного HTML | Запрос страницы под каждым шеллом, `json.loads` атрибута `content=`, утверждение шести ключей, индексов правил и позиции блока | ✓ |
| Чтение исходника шаблонов | Греп шести подстрок в файле include + наличие `{% include %}` в обоих шеллах | |
| И то и другое | Два теста вместо одного | |

**User's choice:** Разбор JSON из отрендеренного HTML
**Notes:** Решающий довод — сломанное Jinja-экранирование кавычек внутри `content='…'` отбросило бы весь конфиг молча, и греп исходника остался бы зелёным.

### Чем утверждается подлинность вендоренного `htmx.min.js`?

| Option | Description | Selected |
|--------|-------------|----------|
| `version` + SHA-384 константой в тесте | Утверждается «именно этот артефакт», а не «версия 2.0.10»; константа = запись о ввезённом | ✓ |
| Только `version` по содержимому | Буквально критерий 1; любой файл с нужной подстрокой пройдёт | |
| SHA-384 + атрибут `integrity` на теге | Проверка уезжает в браузер, но хеш живёт в двух местах и при рассинхроне страница остаётся без htmx молча | |

**User's choice:** `version` + SHA-384 константой в тесте

### Что именно несёт общий include?

| Option | Description | Selected |
|--------|-------------|----------|
| `meta` + тег htmx одной парой | Порядок «конфиг перед рантаймом» становится свойством построения, а не утверждением теста | ✓ |
| Только `meta` | Минимальное вмешательство в шеллы; порядок держится только тестом | |
| Весь общий `<head>` целиком | Снимает дублирование `<head>` разом, но это рефакторинг шире фазы | |

**User's choice:** `meta` + тег htmx одной парой
**Notes:** Вариант «весь `<head>`» отправлен в отложенные идеи.

## Пересчёт asset_version

### От чего считается версия ассетов?

| Option | Description | Selected |
|--------|-------------|----------|
| Glob по `css` + `js` в `app/static` | Дрейфостойко: четвёртый вендоренный файл попадает в расчёт сам. Шрифты вне охвата — тега с `?v=` у них нет | ✓ |
| Явный белый список трёх файлов | Читаемо, но новый файл надо не забыть дописать | |
| Своя версия каждому ассету через `asset_url()` | Точнее всего, но меняет 6 мест вызова и вводит новый контракт | |

**User's choice:** Glob по `css` + `js` в `app/static`

### Чем считается значение версии?

| Option | Description | Selected |
|--------|-------------|----------|
| Хеш содержимого | Версия означает «что отдаётся», а не «когда собирали»; деплой без правок статики не сбрасывает кеш | ✓ |
| `max(mtime)` — расширение текущего | Минимальная правка, для FOUND-03 достаточно | |

**User's choice:** Хеш содержимого
**Notes:** Проверено по `Dockerfile` (`COPY . .`) и `just prod-build` — mtime переживает попадание в образ, так что оба варианта были рабочими; выбор сделан по смыслу значения, а не по работоспособности.

### Когда версия вычисляется?

| Option | Description | Selected |
|--------|-------------|----------|
| На импорте, один раз — как сейчас | Деплой = рестарт, в проде версия всегда свежая; ограничение «ни одного `Settings` на импорте» сохраняется | ✓ |
| Глобал становится вызываемым с кешем | `stat()` трёх файлов на рендер, хеш только при изменении; dev-правки видны без перезапуска | |

**User's choice:** На импорте, один раз

### Фиксируем ли состав охвата инвентарным гейтом?

| Option | Description | Selected |
|--------|-------------|----------|
| Да, именами и числом | По образцу `ROW_DELETE_PLACES = 12`; закрывает пустой glob и незамеченный четвёртый файл | ✓ |
| Нет, только поведенческий тест | Glob и так дрейфостоек; фиксация состава частично его отменяет | |

**User's choice:** Да, именами и числом

## Снимки истории в localStorage

**Установлено по коду до вопроса:** самоочистка в htmx есть уже в 1.9.10 (функция `Kt`), но срабатывает только при попытке сохранить снимок, то есть при `hx-push-url` / `HX-Push-Url`. Единственное такое место сегодня — `app/pages/ads.py:522`.

### Что делаем с уже осевшими снимками?

| Option | Description | Selected |
|--------|-------------|----------|
| Явная очистка на входе в auth-шелл | Одна строка `localStorage.removeItem('htmx-history-cache')` в `auth_base.html`; критерий 4 становится буквально истинным | ✓ |
| Только конфиг | Ни одной строки JS, но критерий 4 закрывается лишь на свежем профиле | |
| Очистка в обоих шеллах | Ключ не переживёт ни одной полной навигации; избыточно после `historyCacheSize: 0` | |

**User's choice:** Явная очистка на входе в auth-шелл
**Notes:** Названо отступлением от рамки вехи «без нового JS» — первый инлайн-`<script>` в проекте.

### Как htmx ведёт себя на промахе кеша истории (Back)?

| Option | Description | Selected |
|--------|-------------|----------|
| Оставить умолчание `false`, шесть ключей | AJAX-GET без `HX-Request`, своп тела полного документа; состав ключей остаётся как в FOUND-02 | ✓ |
| Седьмой ключ `refreshOnHistoryMiss: true` | Back даёт обычную перезагрузку; класс дефектов снимается целиком, но требование надо править | |

**User's choice:** Оставить умолчание `false`, шесть ключей
**Notes:** Риск переинициализации Alpine переезжает в пункт 5 ручного UAT (Фаза 11), где он уже назван.

### Нужен ли гейт на саму строку очистки?

| Option | Description | Selected |
|--------|-------------|----------|
| Да, тест утверждает строку | Наличие и единственность в отрендеренном auth-шелле; снятие роняет тест | ✓ |
| Нет, только ручной UAT | Действие всё равно проверяется глазами в DevTools | |

**User's choice:** Да, тест утверждает строку

## Закрытие ручного обхода

**Установлено по коду до вопроса:** 22 места `hx-get` распадаются на три механизма — `revealed` (10), `every Ns` (10), условная подгрузка через `{% if %}` (2). Отдельно зафиксирована поправка: `scrollBehavior` читается только модификаторами `show:` и `scroll:`, которых нет ни в одном из десяти мест `revealed`.

### В какой форме закрывается ручной обход?

| Option | Description | Selected |
|--------|-------------|----------|
| Чеклист-артефакт в каталоге фазы | `07-UAT.md` по трём механизмам; переживает сброс контекста и кормит GATE-09 в Фазе 15 | ✓ |
| Пунктами в PLAN и VERIFICATION | Меньше сущностей, но Фазе 15 придётся собирать перечень заново | |

**User's choice:** Чеклист-артефакт в каталоге фазы

### Запасной план, если каскад подгрузки воспроизведётся?

| Option | Description | Selected |
|--------|-------------|----------|
| Правим `hx-trigger`, конфиг не трогаем | Ограничитель `intersect` / `once` / порог в десяти местах через общий макрос; FOUND-02 править не надо | ✓ |
| Седьмой ключ `scrollBehavior: 'smooth'` | Одна строка, но по разбору выше на причину скорее всего не действует | |
| Не решать заранее | Фаза встаёт на ручной приёмке без готового решения | |

**User's choice:** Правим `hx-trigger`, конфиг не трогаем

### Заводим ли в Фазе 7 инвентарный гейт на 22 места `hx-get`?

| Option | Description | Selected |
|--------|-------------|----------|
| Да, числом по трём механизмам | Единственная фаза без машинного теста получает хотя бы один; отметка «обошли 22 места» перестаёт тихо устаревать | ✓ |
| Нет, ждём пакет гейтов Фазы 8 | Фаза 7 остаётся чистой заменой рантайма и конфига | |

**User's choice:** Да, числом по трём механизмам

## Claude's Discretion

- Точное имя и внутренняя структура `includes/htmx_config.html`.
- Алгоритм и длина хеша в `_compute_asset_version()`.
- Имена констант в тестах; новые тесты внутри `test_shell.py` или отдельным файлом.
- Формат отметок в `07-UAT.md`.
- Обёртка `try/catch` вокруг обращения к `localStorage` (приватный режим бросает исключение).
- Нарезка фазы на планы.

## Deferred Ideas

- Вынос всего общего `<head>` двух шеллов в один include — рефакторинг шире фазы.
- Обновление Alpine 3.13.3 — вне объёма вехи.
- Своя версия каждому ассету через `asset_url()` — отвергнуто в пользу одной общей версии.
- Седьмой ключ `refreshOnHistoryMiss: true` — вернётся в обсуждение в Фазе 11, если пункт 5 ручного UAT покажет проблему с Alpine.
- Атрибут `integrity=` на теге htmx — кандидат к пересмотру, если появится CSP.
- Браузерный стенд (Playwright) — отклонён на уровне вехи, отложен как `E2E-01`.
