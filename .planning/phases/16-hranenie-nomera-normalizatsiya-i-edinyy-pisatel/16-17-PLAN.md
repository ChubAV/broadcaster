## Решения планирования

- **Одна таблица — три потребителя.** `JUDGED_PARAMETERS` питает предикат (`_bound_arguments`: позиция
  в вызове и имя параметра), правило-сторож сигнатур и правило-матрицу. Подъём библиотеки, сменивший
  имя или позицию параметра, краснит сторож, а не оставляет гейт слепым молча (пин версий отложен
  владельцем — IN-02).
- **Связывание — грамматикой, а не перечнем форм.** `_positional_arguments` раскрывает литеральную
  распаковку `*[…]` / `*(…)` (не-литерал обрывает позиции — дальше поток данных); `_named_arguments`
  раскрывает `**{"имя": …}` и `**dict(имя=…)`. Именованные колонки (`values(phone=…)`) по-прежнему судятся
  своей веткой; раскрытие `**{…}` для них не применяется, иначе `values(**{"phone": x})` дал бы две находки.
- **Ссылка — общий механизм.** Вызов, среди аргументов которого стоит ссылка на судимый API (имя или
  атрибут без вызова, `getattr(obj, "имя")`), судится как вызов этого API с аргументами, стоящими после
  ссылки, плюс аргументы вызова, применённого к нему (`partial(…)(…)`); `fn=` — по сигнатуре `run_sync`;
  `methodcaller("имя", …)` — по строке. Вызов, чей результат тут же вызывается, судится один раз — у
  применения.
- **Вид 1 — по грамматике Python.** `Attribute` в контексте `Store` — все позиции цели присваивания
  сразу; `del` (контекст `Del`) — не запись (замер), в шапке названо.
- **`obj.__init__(phone=…)` у объекта неизвестного типа — в границе с правдивой причиной.** Без типов он
  неотличим от `super().__init__(phone=…)` любого класса; `MessengerAccount.__init__(…)` и псевдоним
  модели в модуле — ловятся.
