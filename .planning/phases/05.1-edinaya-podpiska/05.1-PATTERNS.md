**(a) Скелет, литералы и `logger` — `0019_payment_switch_authorized.py:115-147`:**

> `app.models` — правило ревизий `0013`/`0014`/`0017`/`0018`.

**(b) Место в очереди — `0019`, докстринг (обязателен, закреплён тестом):**

Для `0020` — «ВОСЬМОЙ», перечень до `0019` включительно, литерал `0012` обязан

**(c) Правка данных совместимым SQL ДО изменения схемы — `0018:81-121`:**
```python
_DEACTIVATE_DUPLICATES = sa.text(
    """
    UPDATE subscriptions SET is_active = false
    WHERE is_active
      AND id <> ( ... )
    """
)

def upgrade():
    connection = op.get_bind()

    result = connection.execute(_DEACTIVATE_DUPLICATES)
    deactivated = result.rowcount if result.rowcount is not None else -1
    logger.info(
        "0018: deactivated %s duplicate active subscription row(s); ... "
        "THIS IS NOT REVERSIBLE.",
        deactivated,
    )
```
⚠️ Из комментария над константой — правило, дословно применимое к трём популяциям
`0020` (у `has_free_access` тот же тип):
> `SET is_active = false` — КЛЮЧЕВЫМ СЛОВОМ, НИКОГДА НУЛЁМ. На PostgreSQL
> `is_active` — настоящий boolean, и целочисленный литерал он не принимает;
> тестовая суита идёт по SQLite и этот дефект пропустила бы.

Порядок в `upgrade()` копировать один в один: **сначала три UPDATE/INSERT по
`plan`, потом `op.drop_column("subscriptions", "plan")`** (RESEARCH, Ловушка 4).

**(d) `drop_column` + честный комментарий о потере — `0013_ad_status.py:26-60`:**

из `0009:14-60`** (это схема, которую откат обязан вернуть).

**(f) Несимметричный откат, говорящий вслух — `0018:129-146` / `0019:135-147`:**
