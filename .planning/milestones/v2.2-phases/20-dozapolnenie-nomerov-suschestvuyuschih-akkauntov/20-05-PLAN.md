<objective>
Настоящий признак «TG-аккаунт занят рассылкой», наблюдаемый из контейнера `web`: снимок Celery
`inspect` (`active` ∪ `reserved`) и сообщения очереди `telegram` в Redis, с отказом в закрытую на любой
неопределённости (PHONE-20; D-09, D-07). Волна 5.

Purpose: D-09 требует, чтобы скрипт не подключался к сессии, по которой идёт рассылка, и чтобы это была
защита в коде. Пул TG не используется нигде (RESEARCH A2), а Celery держит клиента секунды на каждую
отправку, поэтому «занят» — это задача отправки аккаунта, выполняемая, предзагруженная или ждущая в
очереди. Цена ошибки «не занят» необратима (ключ убит), цена ошибки «занят» — повторный прогон.

Output: `TelegramBusyProbe` и константы `SEND_TASK`, `TELEGRAM_QUEUE`, `ACCOUNT_ARG_INDEX`,
`INSPECT_TIMEOUT`; двойники инспектора и Redis; трасер через `TelegramSource`; матрица отказа в
закрытую; разбор настоящего сообщения kombu; правила против дрейфа.

  kombu кладёт в список `dumps(message)` того же словаря через `lpush` по ключу `telegram` при приоритете

  список, а не только `inspect`: сообщение, ещё не выданное воркеру, через секунды станет параллельным

- **Требуется ответ воркера очереди `telegram`** (уточнение рекомендации A2, причина — отказ в
  закрытую): `inspect` собирает ответы всех воркеров за таймаут; если ответил только `default`, а
  воркер `telegram` нет, пустой снимок означал бы «не занят» при идущей рассылке. Состав воркеров
  очереди берётся `active_queues()` один раз за прогон; каждый такой воркер обязан быть в ответе
  `active()` и `reserved()` на каждом аккаунте.
- **Аргументы задачи** из `active`/`reserved` — список (`safe=None` → `args` как есть, сериализатор JSON);
  из списка Redis — `json.loads(headers["argsrepr"])`. Нечитаемые аргументы задачи отправки — `None`
  (неизвестно, чья) → «занят».
- **`INSPECT_TIMEOUT = 2.0`** (допущение A8 RESEARCH): слишком малый таймаут даёт «не определён» →
