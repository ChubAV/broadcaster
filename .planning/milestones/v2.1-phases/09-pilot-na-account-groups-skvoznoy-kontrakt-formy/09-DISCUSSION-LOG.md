## Тумблер без submit-кнопки

### Чем защищён тумблер от второго нажатия, если submit-кнопки в его форме при живом Alpine нет?

| Option | Description | Selected |
|--------|-------------|----------|
| Цель — сам чекбокс, записанным исключением | Блокируется тот элемент, которым отправляют; гейт считает исключения ЧИСЛОМ с обоснованием на запись | ✓ |
| Кнопка прячется, а не удаляется | Буква QUAL-01 цела, но чекбокс остаётся кликабелен во время запроса — дыра открыта, атрибут становится ритуалом | |
| Атрибут холостой + `hx-sync="this:drop"` | Гейт зелен на атрибуте, который ничего не делает | |
| Отправка кнопкой, а не по change | Тумблер перестаёт быть мгновенным; кнопка у каждой строки — видимое изменение макета | |

**User's choice:** Цель — сам чекбокс, записанным исключением
**Notes:** → D-06. Проверено по вендоренному htmx 2.0.10: без явного `hx-sync` повторный запрос от того же элемента не глушится. Буква QUAL-01 и критерия 3 роадмапа амендируется записью; дух держится целиком.

### Чем снимается кнопка «Применить» в форме тумблера?

| Option | Description | Selected |
|--------|-------------|----------|
| Снятие привязывается к htmx | Кнопка исчезает ровно тогда, когда её работу забрали; закрывает сценарий «Alpine жив, htmx мёртв» | ✓ |
| Оставить как есть | htmx грузится блокирующе и раньше Alpine, но если сценарий всё же случится — группу нельзя ни включить, ни выключить | |
| Кнопка видима всегда | Самая простая разметка, `CLIENT_STATE_NODES` 24 → 23, но видимое изменение макета | |

**User's choice:** Снятие привязывается к htmx
**Notes:** → D-07. Снято по коду: htmx подключается блокирующе в `<head>` (`includes/htmx_config.html:134`), Alpine — с `defer` (`base.html:26`).

### Что Фаза 9 делает с гейтом границы Alpine?

| Option | Description | Selected |

| Усилить правилом «`x-data` без состояния» | Внутри цели свапа допустим только голый `x-data`; узел с состоянием обязан лежать снаружи | ✓ |

## Состав ответа и OOB

### Что происходит, когда удалена ПОСЛЕДНЯЯ строка?

| Option | Description | Selected |
|--------|-------------|----------|
| `HX-Location` на тот же адрес | `respond()` без `fragment` — уже построенная ветка Фазы 8; второго механизма отрисовки пустого состояния не заводится | ✓ |
| Второй OOB-узел с пустым состоянием | Ничего не мигает, но три ветки пустого состояния придётся звать из двух мест | |
| Ничего — пустая карточка до перезагрузки | Пустая рамка без объяснения и без следующего шага | |

**User's choice:** `HX-Location` на тот же адрес
**Notes:** → D-09.

### Нужна ли плашка `?notice=` на успешный тумблер и на успешное удаление?

| Option | Description | Selected |
|--------|-------------|----------|
| Ни на то, ни на другое | Исход виден в строке и в счётчике; «плашка на каждый успех» — Out of Scope вехи | ✓ |
| Только на удаление | Пользователь только что прочитал то же самое в панели подтверждения | |
| На оба действия | Две плашки на каждое переключение тумблера — ровно тот спам, который вынесен за рамки | |

**User's choice:** Ни на то, ни на другое
**Notes:** → D-10. Побочный выигрыш: пилот доказывает, что ветка `notice=None` работает на обоих транспортах.

### Какой формой удаление снимает строку?

| Option | Description | Selected |
|--------|-------------|----------|
| `hx-swap="none"`, всё едет OOB | Макросу `modal()` не нужен параметр цели — все 16 мест одинаковы, рычаг Фазы 10 остаётся одной правкой | ✓ |
| `hx-target` на строку + `outerHTML` пустотой | Рычаг Фазы 10 превращается в 16 разных вызовов | |
| Ответ перерисовывает контейнер списка | Прямо запрещено критерием 1 и сломало бы бесконечную прокрутку | |

**User's choice:** `hx-swap="none"`, всё едет OOB
**Notes:** → D-11. Тумблер, наоборот, идёт `hx-target` + `outerHTML` — критерий 4 требует доказать факт свапа. Фаза доказывает обе ветки GATE-05 сразу.

### Форма OOB-областей на всю веху?

| Option | Description | Selected |
|--------|-------------|----------|
| Постоянная обёртка + подмена СОДЕРЖИМОГО | `innerHTML:#id`, идиома области уведомлений (FOUND-06); «забыли отрисовать — исчезло навсегда» становится невыразимым | ✓ |
| Подмена УЗЛА (`hx-swap-oob="true"`) | Как у сегодняшнего `autosave_response.html`; узел обязан приезжать с тем же `id` каждый раз | |
| Решать по месту | Фаза 11 приняла бы это решение 15 раз заново; гейт на форму OOB стал бы невыразимым | |

**User's choice:** Постоянная обёртка + подмена СОДЕРЖИМОГО
**Notes:** → D-12. Форма на всю веху.

## Вид «запрос идёт»

### Где живёт индикатор, раз его раздаёт ОДИН макрос на 47 форм?

| Option | Description | Selected |
|--------|-------------|----------|
| Макрос рисует его сам, внутри формы | Один класс, одна разметка, ноль решений на 47 вызовов — ровно то, чего требует FORM-09 | ✓ |
| Индикатор — строка целиком | Заметнее, но макрос принимает селектор от вызывающего, и решение принимается 47 раз | |
| Общая полоса вверху экрана | Не говорит, КАКОЕ из действий экрана сейчас идёт | |
| Только заблокированная кнопка | Не закрывает QUAL-02 и не работает на тумблере, где кнопки нет | |

**User's choice:** Макрос рисует его сам, внутри формы
**Notes:** → D-14. Видимость блокировки кнопки уже отгружена (`.btn[disabled]`), что записано докстрингом `modal.html`.

### Каков порог видимости через `transition-delay`?

| Option | Description | Selected |
|--------|-------------|----------|
| 300 мс | Классический порог «пользователь не заметил»; в норме не мигает, на медленной сети появляется вовремя | ✓ |
| 150 мс | Честнее показывает факт запроса, но мигает на каждое нажатие | |
| 500 мс | Полсекунды без обратной связи читаются как «кнопка не сработала» и провоцируют повторное нажатие | |

**User's choice:** 300 мс
**Notes:** → D-15.

### Что делает экран, когда запрос тумблера провалился, а чекбокс уже переключён браузером?

| Option | Description | Selected |
|--------|-------------|----------|
| Строка приезжает с сервера и при отказе | Рисуется НАСТОЯЩЕЕ состояние, а не ожидаемое; оптимистичным остаётся только «сервер не ответил вовсе» | ✓ |
| Только плашка, текст не трогаем | Экран молча расходится с сервером до F5, а пользователь читает тумблер как истину | |
| Откат тумблера клиентом | Новый обработчик `htmx:responseError` против рамки «минимум нового JS»; третий такой покрасил бы инвентаризацию | |

**User's choice:** Строка приезжает с сервера и при отказе
**Notes:** → D-16. Текст плашки `#htmx-failure-network` дополняется одной строкой о возможном расхождении экрана с сервером.

### Что отвечает тумблер над не найденной или чужой группой?

| Option | Description | Selected |
|--------|-------------|----------|
| `HX-Location` на экран групп | Та же ветка, что у «удалена последняя строка»; «нет такой» и «чужая» остаются неотличимы друг от друга | ✓ |
| Тот же OOB-снос строки, что у удаления | Счётчик и пустое состояние пришлось бы вести второй веткой и в тумблере тоже | |
| Обе ветки — `HX-Location` | Неотличимость полная, но тумблер вообще не возвращает фрагмент — критериям 1 и 4 нечего доказывать | |

**User's choice:** `HX-Location` на экран групп
**Notes:** → D-13.
