# Phase 08 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

Реестр собран из `<threat_model>` одиннадцати планов фазы (08-01…08-11) и блоков
`## Threat Flags` девяти сводок. Все одиннадцать планов несут собственный блок
угроз, поэтому реестр авторский, а не восстановленный задним числом
(`register_authored_at_plan_time: true`). Уровень ASVS 1 — глубина проверки
грепом по исходникам; аудитор не вызывался по правилу короткого замыкания.

⚠️ **Гигиена реестра.** Идентификаторы `T-08-30`, `T-08-32`, `T-08-33`, `T-08-34`
переиспользованы РАЗНЫМИ планами под РАЗНЫЕ угрозы (например `T-08-33` — это и
шелл-гейт G-23 в 08-04, и счётчик уборки в 08-05, и адрес фрагментного маршрута
в 08-08). На меры это не влияет — каждая закрыта в своём плане, — но при сводном
чтении реестра строка по одному идентификатору неоднозначна. Дефект записей, не
кода; исправление — за будущей фазой.

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| браузер → зависимость страницы | заголовок `HX-Request` приходит от клиента и целиком им управляем | признак транспорта |
| приложение → браузер (заголовки ответа) | `HX-Location` приказывает браузеру уйти по адресу | локальный путь |
| адресная строка → обработчик | `redirect=` и `notice=` собираются кодом; соседние параметры — от владельца ссылки | код исхода |
| адресная строка → область уведомления | один параметр рисует плашку на КАЖДОЙ странице обоих шеллов | код исхода |
| ответ сервера → инлайн-сценарий | сценарий читает свойство ответа и меняет DOM на всех страницах | код состояния HTTP |
| фрагмент ответа → внеполосная подмена | внеполосный блок способен изменить область за пределами цели свопа | разметка плашки |
| форма оплаты → сервис | две одновременные отправки одной кнопки приходят как два независимых запроса | намерение оплаты |
| сервис → ЮKassa | единственное обращение наружу на денежном пути | сумма, идентификатор платежа |
| приложение → СУБД | ограничение схемы становится авторитетным потолком | денежные строки |
| СУБД → пользователь | текст отказа ограничения содержит внутренние имена | текст `IntegrityError` |
| исходник/шаблоны репозитория → гейт | гейты читают текст, а не собранное приложение | дерево репозитория |
| артефакт развёртывания → работающая защита | удержание в памяти верно ровно при одном процессе | `docker-compose.prod.yml` |
| перечисление статусов → его читатели | новый член перечисления пересекает границу молча, если читатель задан ДОПОЛНЕНИЕМ | `payments.status` |
