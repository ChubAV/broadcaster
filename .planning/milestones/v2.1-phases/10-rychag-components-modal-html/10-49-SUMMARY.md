## Замер вендоренного рантайма — дословно, обе половины

Источник: `app/static/js/htmx.min.js` (вендоренный артефакт, 51238 байт). Выдержки сняты грепом по исходнику 2026-09-11, а не взяты из памяти.

**(а) Признак успеха есть ОТРИЦАНИЕ признака провала:**

```
e.target=r;e.failed=a;e.successful=!a;if(m.shouldSwap){…}
```

Третьего значения у признака нет; ставятся оба на объекте сведений об ответе, ВНУТРИ разбора ответа — то есть ДО того, как поднимется событие завершения на пути загрузки.

**(б) На пути ОБРЫВА ТРАНСПОРТА объект этих признаков НЕ ПОЛУЧАЕТ ВОВСЕ:**

```
g.onerror=function(){rn(R,q);fe(r,"htmx:afterRequest",T);fe(r,"htmx:sendError",T);re(l);m()};
```

Разбор ответа здесь не исполняется — значит `T` приходит в обработчик БЕЗ признаков, и событие завершения поднимается ПЕРЕД событием отказа отправки. Отсюда предикат: проверяется ОТСУТСТВИЕ признака успеха, а не сравнение его с ложью (D-49-2).

**(в) Третья выдержка, снятая попутно и решившая порядок на пути неуспешного ОТВЕТА:**

```
if(a){fe(t,"htmx:responseError",le({error:"Response Status Error Code "+n.status+" from "+e.pathInfo.requestPath},e))}
```

Событие отказа ответа поднимается в КОНЦЕ разбора, то есть ДО `htmx:afterRequest` в `g.onload`. Обработчик без раннего выхода погасил бы заготовку, поднятую отказом мгновением раньше, — плашка гасла бы собственным отказом ещё вернее, чем на пути обрыва.

Доктóренная копия, где сценарий снимает признак и тут же ставит его обратно, МЕНЯЕТ вердикт гарнира:

| Исходник | События | Вердикт |
|---|---|---|
| настоящий | отказ отправки | `{'htmx-failure-server': True, 'htmx-failure-network': False}` |

Значит снятие и постановка признака не проглатываются стабом, и правило не зеленело бы на обработчике с пустым телом.
