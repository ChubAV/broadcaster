### `focus_after_hide` — закрытие при ОТСОЕДИНЁННОМ открывателе

```json
{"attempted": ["cancel", "landing"], "focused": "landing", "open_after": false, "opener_connected": false, "opener_has_focus_method": true, "repeat_matches": true}
```

Отрицательный контроль, тот же сценарий на стаб-документе БЕЗ площадки:

```json
{"attempted": ["cancel"], "focused": "cancel", "open_after": false, "opener_connected": false, "opener_has_focus_method": true, "repeat_matches": true}
```

⚠️ **Поле `opener_has_focus_method: true` при `opener_connected: false` — это и есть предмет.** Метод у отсоединённого узла ЕСТЬ; до правки вердикт этого же сценария был `focused: "opener"` при неимитирующем стабе — то есть в браузере фокус остался бы на теле документа.

### `focus_after_teardown` — снос открытой панели, `hide()` не зовётся ни разу

```json
{"attempted": ["cancel", "landing"], "focused": "landing", "has_destroy": true, "open_after": false, "repeat_matches": true, "still_locked_after_teardown": false}
```

Отрицательный контроль (площадки нет):

```json
{"attempted": ["cancel"], "focused": "cancel", "has_destroy": true, "open_after": false, "repeat_matches": true, "still_locked_after_teardown": false}
```

### `focus_untouched_by_closed_sibling` — снос ЗАКРЫТОЙ соседки при открытой панели

```json
{"attempted": ["cancel"], "focused_after": "cancel", "focused_before": "cancel", "has_destroy": true, "repeat_matches": null, "still_locked_after_teardown": true}
```

Тот же сценарий на выражении с путём сноса БЕЗ СТРАЖА собственного состояния (подстановка `_xdata_with_unguarded_teardown`):

```json
{"attempted": ["cancel", "landing"], "focused_after": "landing", "focused_before": "cancel", "has_destroy": true, "repeat_matches": null, "still_locked_after_teardown": false}
```

### `exchange` — обе ветви по успешности

```json
{"failure": {"locked": true, "open": true, "sending": false}, "repeat_matches": true, "success": {"locked": false, "open": false, "sending": false}}
```

**Поле `repeat_matches: true` стои́т у всех сценариев, прогоняемых дважды.** У сценария соседки его нет по построению — он однопроходный, ровно как действующий сценарий блокировки прокрутки, и повторяемость там сняли бы два независимых объекта в одном прогоне.

## Decisions Made

- **`destroy()` зовёт ТО ЖЕ приземление с тем же аргументом (`this.opener`), а не приземляется безусловно.** Правило одно на обе ветви — этого и требует «объявлено один раз». Следствие названо: открыватель, ПЕРЕЖИВШИЙ снос панели (снос по другой причине, чем уход строки), получает фокус обратно, как и на ветви `hide()`. На фрагментном пути открыватель уезжает вместе со строкой, поэтому там ветвь всегда приводит на площадку — и сценарий `focus_after_teardown` исполняется именно с ОТСОЕДИНЁННЫМ открывателем, то есть воспроизводит фрагментный путь, а не удобный случай.
- **Стаб-узел гарнира фокусируется ТОЛЬКО при присутствии в документе.** Первая редакция записывала имя безусловно, и вердикт до правки читался `focused: "opener"` — то есть гарнир сообщал об успехе там, где браузер не делает ничего. Ошибка поймана на собственном RED-прогоне и исправлена ДО коммита RED: неимитирующим стаб обязан быть ровно там, где предмет, а предмет здесь — где оказался фокус.
- **Собственные разборщики сигнатуры и умолчаний в гейте D-16 сняты в пользу резолюции γ1.** Разобрано в отклонениях: два резолвера одной операции разошлись бы молча.
- **`FORM-06` НЕ отмечено выполненным.** Требование объявляют все четыре плана фазы; общий идентификатор не имеет права читаться `Complete`, пока не финишировал последний.
