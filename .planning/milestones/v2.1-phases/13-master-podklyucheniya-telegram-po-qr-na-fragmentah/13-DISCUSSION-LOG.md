## Сохранение аккаунта после сканирования

| Option | Description | Selected |
|--------|-------------|----------|
| Сразу в опросе (Рекомендуется) | Сервер создаёт аккаунт тем же запросом опроса, который увидел «отсканировано»; потеря — только если вкладку закрыли в первые ~3 с; `complete` исчезает, опрос становится POST | ✓ |
| Двумя шагами, как сейчас | Опрос показывает «отсканировано», следом страница сама шлёт complete; окно как сегодня | |
| Даже при закрытой вкладке | Фоновая задача сохраняет аккаунт в момент сканирования; окна нет, но запись в базу вне запроса, больше кода | |

**User's choice:** Сразу в опросе.
**Notes:** Остаточное окно (~3 с) записано в D-01 как принятое.

---

## Истечение QR-кода

| Option | Description | Selected |
|--------|-------------|----------|
| Кнопка «Обновить» (Рекомендуется) | «QR-код истёк» + кнопка, одно нажатие — новый код; так записан критерий 4 | ✓ |
| Обновлять автоматически | Сервер сам выдаёт новый код каждые ~30 с до 5 минут, потом «Начать заново»; забытая вкладка продолжает ходить в Telegram | |

**User's choice:** Кнопка «Обновить».
**Notes:** Попутно записан корень D-03: таймаут `QRLogin.wait()` (~30 с) сегодня превращается
в «Ошибка авторизации» без выхода, а ветка `expired` срабатывает только через 300 с.

## Claude's Discretion

D-03…D-13 приняты по умолчанию при делегировании: оживление ветки истечения, добавление
проверки владения сессией (критерий 3 ошибочно говорит «сохранена»), форма фрагментов и якоря,
`session_id` в скрытом поле, успех без автоперехода, 422 для неверного пароля 2FA, отказы
фрагментом с «Начать заново», путь слоя ответа без сессии, деградация без JS не строится,
снятие старого со сдвигом инвентарных чисел, границы правки слоя мессенджера.
