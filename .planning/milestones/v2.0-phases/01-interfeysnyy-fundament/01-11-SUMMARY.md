## Контракт панели подтверждения — сверяться Планам 12-13

```jinja
{# в форме — перехват отправки, ссылающийся на идентификатор панели #}
<form method="POST" action="/accounts/{{ account.id }}/delete"
      x-data x-on:submit.prevent="$dispatch('modal-open-acc-del-{{ account.id }}')">
  {{- button('Удалить', variant='ghost', icon='trash', title='Удалить аккаунт') -}}
</form>

{# панель — СОСЕДНИМ элементом строки, одна на аккаунт #}
{{ modal(id='acc-del-' ~ account.id,
         title='Удалить аккаунт?',
         action='/accounts/' ~ account.id ~ '/delete',
         confirm_label='Удалить',
         method="post",
         body=label ~ ' #' ~ account.id) }}
```

| Что | Значение |
|---|---|
| Идентификатор панели | `acc-del-<id>` |
| Имя события открытия | `modal-open-acc-del-<id>` (генерируется макросом из `id`) |
| Эмитят панель | `accounts/list.html`, `accounts/partial_cards.html` |
| НЕ эмитит панель | `accounts/partials/sync_status_card.html` |
| Эмитят событие | все три файла, по 3 места в каждом |
| Поясняющий текст | название канала и номер аккаунта (`WhatsApp #7`) |

**Почему `method="post"` передаётся явно, хотя совпадает с умолчанием макроса:** маршрут и метод удаления — контракт с обработчиком, и он обязан читаться грепом по файлу раздела, а не только по отрендеренной странице. Тот же приём, что в эталоне `ads/includes/ad_card.html`.

## Сознательная асимметрия файла подмены

`accounts/partials/sync_status_card.html` несёт форму с перехватом отправки, но **не эмитит панель**. Причина записана в шапку файла рядом с механизмом остановки опроса:

- Заменяется РОВНО строка (`hx-swap="outerHTML"` стоит на самой строке). Панель лежит вне заменяемого элемента и подмену переживает.
- Эмить панель ещё и здесь — после первого же опроса в документе две панели с одинаковым идентификатором: событие открывает обе, Tab уходит в невидимую копию (T-11-04).
- Обратная ошибка — поставить панель ВНУТРЬ строки — сделала бы её присутствие обязательным во всех трёх файлах и молча потеряла бы кнопку удаления в момент подмены.

Расхождение закреплено **явным утверждением** в `test_accounts_three_files_dispatch_same_modal_event`, а не исключением из общего сравнения: `components/modal.html` обязан присутствовать в двух файлах и отсутствовать в третьем.

## Окончательный набор подписей раздела

`ACCOUNT_COLUMNS` объявлен теперь во всех трёх файлах дословно одинаково:

```jinja
{% set ACCOUNT_COLUMNS = ['Аккаунт', 'Групп', 'Расписаний', 'Успешность', 'Последняя отправка', 'Подключён', 'Статус', ''] %}
```

| Индекс | Колонка | Подпись в ячейке |
|---|---|---|
| 0 | Аккаунт | **нет** — колонка и есть заголовок карточки, подпись была бы удвоением |
| 1 | Групп | да |
| 2 | Расписаний | да |
| 3 | Успешность | да |
| 4 | Последняя отправка | да |
| 5 | Подключён | да |
| 6 | Статус | да — без неё бейдж «Отключён» на телефоне висит в воздухе |
| 7 | (действия) | **нет** — колонка названия не имеет |

**18 подписей на файл** = 6 колонок × 3 ветки статуса. Подпись передаётся ИНДЕКСОМ (`label=ACCOUNT_COLUMNS[1]`), а не строкой; строковый литерал в позиции подписи отвергается тестом.

Подписи проставлены и на ячейках с прочерком: именно из-за них строка на телефоне превращалась в набор символов — прочерк без подписи не сообщает, чего именно нет.

Рендер:
```html
<span class="cell cell--mono cell--muted" title="Групп"><span data-cell-label>Групп</span>3</span>
```
Атрибут подсказки сохранён: он полезен указателем мыши на широкой ширине, где подпись скрыта правилом `app.css:1133`.
