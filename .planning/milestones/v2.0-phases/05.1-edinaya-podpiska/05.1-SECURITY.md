# Phase 05.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

Фаза сняла счётную (per-message credit) модель тарификации и поставила на её место
единую подписку, гейтящую доступ к продукту. Реестр угроз авторствовался НА ЭТАПЕ
ПЛАНИРОВАНИЯ — `<threat_model>` присутствует во всех 14 планах фазы
(`register_authored_at_plan_time: true`), поэтому ретроактивный STRIDE не проводился:
аудит проверял наличие объявленных митигаций, а не искал новые угрозы.

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| браузер → страничные маршруты (cookie-аутентификация) | недоверенный вход; здесь же новая граница АВТОРИЗАЦИИ по доступу | сессионная cookie, вердикт доступа |
| JSON-клиент → `app/routes/*` (Bearer или cookie) | недоверенный вход; новая граница авторизации по доступу | токен, вердикт доступа |
| форма оплаты → `POST /billing/subscribe` → SDK ЮKassa | пользователь инициирует денежную операцию; сумма не имеет права приходить с этой стороны | инициация платежа (без полей формы) |
| ЮKassa → `POST /api/billing/webhook` | внешняя система пишет в нашу базу; единственный писатель `expires_at` | уведомление об оплате, срок доступа |
| наш сервер → ЮKassa (`YooPayment.create`) | текст назначения уезжает ТРЕТЬЕЙ СТОРОНЕ: страница оплаты, фискальный чек, кабинет мерчанта | назначение платежа, сумма |
| приложение → Redis | кэш вердикта авторизации хранится вне процесса | `access:{user_id}`, TTL 60 с |
| `request.state.shell` → Jinja-разметка на 26 маршрутах | вердикт авторизации пересекает границу «сервер → разметка»; разметка гарантий не даёт | вердикт доступа |
| строки журнала платежей → разметка | контекст несёт строки платежей целиком, включая идентификатор платежа ЮKassa | платёжные строки |
| строка журнала `payments` → экран истории платежей | значение из прошлого печатается человеку сегодня; переименование задним числом — ложь в денежном журнале (D-H) | историческое назначение платежа |
| Celery beat / worker → база (вне HTTP) | исполняется без пользователя и без сессии запроса; отказ здесь снаружи не виден | расписания, отправки |
| строка подписки → предикат доступа | признак бесплатного доступа становится входом решения об авторизации | `has_free_access` |
| кэш вердикта доступа → путь отправки и страницы | вердикт читается из кэша, а меняется тумблером в обход кэша | вердикт доступа |
| администратор → `app/pages/admin.py`, `POST /admin/users/{id}/unlimited` | привилегированные операции над чужими учётными записями; выдача платного блага | срок доступа, льгота |
| ревизия Alembic `0020` → боевая база | единственная необратимая по данным операция фазы; вне тестового окружения | три популяции подписок, журнал сообщений |
| боевая база → дамп → копия → репозиторий | персональные данные живых людей покидают боевой периметр; дамп в репозитории попадает в историю навсегда | адреса эл. почты, хеши паролей |
| исполнитель → боевой стек | граница прямого запрета: ни одна команда исполнителя не доходит до боя | команды наката |
| исходники `app/` → машинный гейт по грепу | гейт читает ИСХОДНИК, а не импортирует модуль: имя в мёртвой ветке пересекает границу молча | имена снятой счётной модели |
| `app.constants` → две независимые поверхности одного значения | расхождение двух записей одной формулировки видно на боевом платеже | `SUBSCRIPTION_DESCRIPTION` |
| планировочный документ → докстринг ревизии / реестр требований | число или отметка, не сверенные со свидетельством, закрепляются как правда | состояния требований, счётчики |
| человек → judgment-прохибиция | вердикт по формулировке выносит человек; машинное прочтение неавторитетно | вердикт приёмки |

### Остаточные наблюдения

Все четыре ниже порога `block_on: high`; ни одно не переведено в OPEN.

1. **T-05.1-03 — форма утверждения.** Реестр объявлял «тест дорожки утверждает **200**»;
   исполненный тест утверждает `status_code in (200, 302)` И `location != "/billing?expired=1"`
   (`tests/test_pages/test_access_gate.py:215-220`), отклонение обосновано докстрингом
   `:206-211`. Вектор угрозы — запирание продукта — покрыт утверждением о `location`
   полностью.
2. **T-05.1-28 — равенство есть факт, а не инвариант.** Потолок и число записей сегодня
   оба равны 21, но принуждающее утверждение — `len(entries) <= WITHOUT_WITNESS_CEILING`.
   Будущий план может поднять потолок выше числа и тихо вернуть запас. Замена `:600` на
   `==` сделала бы объявленное «потолок в точности равен» машинно закреплённым.
3. **T-05.1-33 — на админской стороне нет регрессии.** `test_the_screen_never_prints_the_yookassa_payment_id`
   стережёт ПОЛЬЗОВАТЕЛЬСКИЙ экран подписки, не админские поверхности. Админские сегодня
   чисты (греп + словарь из четырёх ключей), но ничто не покраснеет, если будущий план
   добавит идентификатор платежа в админскую карточку.
4. **T-05.1-13 — область гейта уже счётчиков, которые он защищает.** `tests/test_planning/`
   сверяет `progress` в STATE.md с отметками планов в ROADMAP; арифметику §Coverage
   (41 = сумма по фазам) он НЕ проверяет. Сегодня она верна по осмотру, но машинно не держится.
