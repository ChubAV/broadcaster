## Механика продления

### Что происходит при нажатии «Продлить»

| Option | Description | Selected |
|--------|-------------|----------|
| Настоящий платёж ЮKassa | Тот же путь, что у пакетов: create_payment → редирект → вебхук двигает expires_at. Цена: миграция Payment | ✓ |
| Продление без оплаты | Кнопка сразу двигает expires_at, деньги берутся вне продукта. Риск: подписка раздаётся бесплатно | |
| Заявка админу | Запрос на продление, админ подтверждает в Фазе 6. Критерий 1 в этой фазе невыполним | |

**User's choice:** Настоящий платёж ЮKassa
**Notes:** Платёжный контур уже работает и идемпотентен — переиспользуется, а не дублируется.

### Когда появляется строка Subscription

| Option | Description | Selected |
|--------|-------------|----------|
| Только при первой оплате | Free = отсутствие строки; ровно контракт, по которому шелл уже живёт. Ни миграции данных, ни записи на рендере | ✓ |
| Лениво на /billing | get_or_create по образцу баланса. Но шелл явно запрещает запись на рендере (common.py:406) | |
| Backfill всем + при регистрации | У каждого всегда есть строка. Цена: миграция данных на базе, которая ещё на 0012, плюс правка регистрации | |

**User's choice:** Только при первой оплате
**Notes:** —

### Что входит в фазу — продление или смена тарифа

| Option | Description | Selected |
|--------|-------------|----------|
| Продление + первая покупка | Free может купить платный, платный может продлить свой. Переход Basic↔Pro отложен | ✓ |
| Любая смена тарифа | Включая понижение Pro→Basic. Требует правил об остатке оплаченного срока | |
| Строго только продление | С решением «подписка рождается оплатой» это тупик: никто не сможет начать платить | |

**User's choice:** Продление + первая покупка
**Notes:** Переход Basic↔Pro вынесен в отложенные идеи.

### Как считается новый срок

| Option | Description | Selected |
|--------|-------------|----------|
| От текущего expires_at | max(сегодня, expires_at) + 1 месяц. Продление заранее не сжигает остаток | ✓ |
| Всегда от сегодня | Одна формула без веток, но продлённый заранее теряет оплаченные дни | |
| Продление только в окне | Кнопка активна лишь в последние N дней. Главная кнопка раздела большую часть времени неактивна | |

**User's choice:** От текущего expires_at
**Notes:** —

## Claude's Discretion

- Что видит пользователь после возврата с ЮKassa до прихода вебхука (при условии, что срок ещё не сдвинут).
- Вид метра при безлимитной оси (`∞` у Pro).
- Считать ли черновики в оси «Объявления».
- Поведение метра при превышении лимита.
- Точный технический потолок списка платежей и формулировка при срабатывании.
- Порядок блоков в пределах решения об одном экране, подписи, имена макросов и паршалов.
- Судьба JSON-API `app/routes/billing.py` после перевода покупки на форму.
- Значение `kind` по умолчанию для существующих строк `Payment` после миграции.
- Порядок объявления маршрутов и место обработчика формы оплаты.
