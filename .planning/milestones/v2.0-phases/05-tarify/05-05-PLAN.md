Три паршала в `app/templates/billing/includes/`. Все три — **макросы, а не include**:
импортированные шаблоны Jinja контекста вызывающего не получают, поэтому каждый
параметр объявляется явно. Ошибка в имени параметра проявится не исключением, а пустым
блоком при статусе 200 — поэтому каждый макрос получает комментарий-докстринг той же
формы, что у плитки метрики дашборда: что рисует, почему макрос, и строка импорта.

Файлы остаются в `billing/includes/`, **не в `components/`**: они специфичны для
тарифов и в других разделах не переиспользуются, а инвентаризация общей библиотеки
держит жёсткое число файлов, которое обязано остаться верным.

**`plan_card.html` — макрос `plan_card(plan, current_plan, payments_enabled)`.** Состав
по макету: шапка «имя плана + моношрифтовый тег» на одной базовой линии — тег
«ВАШ ПЛАН» у текущего, «БЕЗ ЛИМИТОВ» у плана без лимитов по объявлениям и группам;
крупная цена с периодом «/ мес» рядом; четыре строки «подпись слева — значение
моношрифтом справа» в порядке Объявлений, Групп, Отправок в месяц, Аккаунтов;
кнопка внизу. Безлимитное значение (`None` в записи плана) рисуется знаком
бесконечности. Текущий план выделяется рамкой акцентного цвета.

Кнопка ветвится по состоянию: у текущего платного плана — форма продления
(`method="post"`, `action="/billing/subscribe"`, скрытое поле с идентификатором плана,
подпись «Продлить»); у платного плана, когда текущий Free, — та же форма с подписью
«Перейти на Basic» / «Перейти на Pro»; у плана Free — неактивная подпись «Текущий на
старте» без формы. **Настоящая форма, ни одного обработчика события**: базовый путь
обязан работать без Alpine. Гард двойного нажатия, если он появится, — прогрессивное
улучшение поверх работающей формы, а не условие её работы. При выключенных платежах
карточки рисуются целиком, а вместо кнопки — подпись про администратора, той же формы,
что уже стоит у пакетов.

**`usage_meters.html` — макрос `usage_meter(axis)`.** Одна ось: подпись вида
«Объявления — 6 / 15» и шкала через готовый макрос `progress`, который клампит
диапазон сам. Безлимитная ось (`limit` равен `None`) шкалы не рисует вовсе — на месте
знаменателя знак бесконечности и короткая подпись; заливать шкалу полностью значило бы
сообщить «израсходовано всё» там, где израсходовать нельзя. Деление на лимит выполняется
**только под условием** — исходная разметка неподключённого шаблона на этом уже
падала. Превышение оформляется без тревожного варианта: шкала на сотне, подпись
сообщает настоящие числа.

**`payment_row.html` — макрос `payment_row(payment, user, cols)`.** Раскладка дословно
по образцу истории операций того же раздела: `rowhead` для шапки, `row_open` / `cell` /
`row_close` для строк. Колонки: Дата, Назначение, Сумма, Статус. Подпись колонки едет
вместе со значением через `data-cell-label` — на 860px шапка колонок скрывается, и без
подписи число теряет смысл. Дата — через существующий глобал форматирования даты в зоне
пользователя, свой формат в шаблоне не заводится. Назначение собирается по виду платежа:
для подписки «<План> · продление» либо «<План> · первый платёж», для пакета — название
пакета; форма подписи взята из макета админки, чтобы одно и то же состояние называлось
одним словом у пользователя и у администратора. Статус — бейджем, словарь подписей в
вызывающем шаблоне: `succeeded` → «проведён» (успех), `canceled` → «отклонён» (опасность),
`pending` → «в обработке» (нейтраль); формулировки взяты из макета админки. Неизвестный
статус рисуется моношрифтом как есть, а не прячется. **Элементов таблицы в разметке нет
ни одного** — их запрещает инвентаризация шаблонов по всему проекту.

**Форматирование суммы.** В `app/pages/common.py`, рядом с существующими Jinja-глобалами,
объявить глобал форматирования денежной суммы: принимает машинную строку вида `1490.00`
и возвращает подпись с разделителем разрядов и знаком рубля. Форматирование живёт
**только на стороне показа**: в конфиге и в `amount.value` ЮKassa остаётся машинная
строка, потому что строка с разделителем разрядов — отказ платёжного API в проде,
который не поймает ни один мок. Копейки, равные нулю, не показываются.

**CSS.** В `app/static/css/app.css` — одно новое правило `[data-plans]`: сетка
`repeat(auto-fit, minmax(260px, 1fr))` с тем же зазором, что у соседних сеток. Правило
`[data-metrics]` переопределять **нельзя**: его держат плитки дашборда Фазы 4, и оно
объявлено с меньшим минимумом, чем требует макет карточек. Форма правила копируется у
соседа, значение берётся из макета. Это единственное новое правило CSS, обязательное
фазе: карточку, шкалу, бейдж, моношрифт и вертикальную раскладку закрывают уже
существующие компоненты и примитивы.
