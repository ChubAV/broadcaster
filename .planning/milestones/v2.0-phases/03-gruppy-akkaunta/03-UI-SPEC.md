## Spacing Scale

Declared values for **all new Phase 3 markup**. Primary scale is the standard 8-point set (4, 8, 16, 24, 32, 48, 64) — only the steps this phase uses are listed. The Phase 2 `md` 12px step is **not** part of the primary scale; it survives only as documented Exception 4 below.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between a status dot and its caption, inline gaps inside mono captions |
| sm | 8px | Gap between group rows; gap between the per-row controls («×», toggle); gap between the header action buttons |
| lg | 16px | Group-row padding (`16px`); gap between the avatar, the name column and the controls inside a row; header card internal gaps |
| xl | 24px | Page-level rhythm between the page head and the screen body |
| 3xl | 48px | Empty-state padding — inherited from the shipped `.empty` class, not re-declared |

**Fixed control sizes (multiples of 4):**

| Control | Size |
|---------|------|
| Account icon plate in the header | 48 × 48 (mockup 46 → rounded up) |
| Group avatar (initials) | 32 × 32 |
| Icon button «×» (delete) | 36 × 36 (mockup 34 → rounded up to the touch minimum) |
| Group row min-height | 64 (padding 16 + 32 avatar) |
| Header action buttons | height 40 |

**Exceptions (documented, deliberate):**

1. **Phase 1 macros keep their mockup-literal values** — `.card` (18/20), `.toggle` (38×22 track), `.empty` (48/20), `.badge` (4/9), `.filters`. Reused unchanged, not restyled (same exception as the approved Phase 2 contract).
2. **Toggle track is 22px tall.** Mitigation: the toggle is wrapped in a `<label class="toggle">` whose hit area spans the full 36px-plus control zone of the row. No bare 22px hit target ships.
3. **Status dots are 8px** decorative circles (mockup 6–7px, rounded up to the scale). Non-interactive.
4. **12px intermediate step** — used only for the vertical gap between the header card, the sync-result block, the counter line and the list, and for gaps inside the header identity column. Justification: inherited from the approved Phase 2 contract (its `md` step, `02-UI-SPEC.md` line 61, same usage class — vertical rhythm inside one screen section); mockup value 13px rounds down to it. It is deliberately kept out of the primary scale and must not spread to any other usage in this phase.
5. Remaining mockup gap values 9/14/15px are rounded to the nearest primary-scale step (9→8, 14→16, 15→16); the 13px gaps round down to the 12px exception above — the established Phase 1/2 precedent.

## Color

| Role | Value | Token | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `#08080b` / `#0e0e14` | `--bg` / `--surface` | Page background; the header card and every group row |
| Secondary (30%) | `#12121a` / `#0f0f16` | `--surface-input` / `--surface-pill` | Search input, status pill in the header, sync-result plashka shell |
| Accent (10%) | `oklch(0.72 0.19 310)` | `--accent`, `--accent-cta` | See reserved-for list below |
| Destructive | `oklch(0.68 0.19 25)` | `--danger` | Destructive actions and error copy only |
| Warning | `oklch(0.82 0.16 85)` | `--warn` | «не найдена при синке» marker only |

**Accent reserved for — exhaustive list. Any accent use not on this list is a checker failure:**

1. The single primary CTA of the screen — «Синхронизировать всё» (`.btn--primary`, `--accent-cta`), exactly as the mockup renders it.
2. The **on** state of a group toggle track (`--accent`).
3. Focus ring (`--focus-ring`) on every keyboard-focusable control.
4. The «синхронизация» in-flight status caption + dot while the account is `syncing` (mockup behaviour: the in-flight state carries the accent).

**Explicitly not accent:** «К аккаунтам», the search field, «Применить»/«Сбросить», counter line, «ВЫКЛЮЧЕННЫЕ ГРУППЫ ПРОПУСКАЮТСЯ ПРИ РАССЫЛКЕ», group sub-captions, the «×» delete button at rest, «Настроить группы» on `/accounts`. These are `--text-muted` / `--text-secondary`, with `--text` on hover only.

**Destructive reserved for:** the «×» delete button hover state (mockup: red tint background + `--danger` glyph), the confirm button of the delete modal (`.btn--danger`), `alert(..., 'error')` for a failed sync, and the `sync_failed` status caption.

**Warning reserved for:** the «не найдена при синке» dot + mono caption (D-11 marker). It never colours the row itself.

**Channel colours** come from `messenger_icon` (`--info` Telegram, `--ok` WhatsApp, MAX its own gradient) and tint the header icon plate and the group avatar initials. They mark channel identity only and never mark state.

**Disabled group row:** `opacity: .55` on the row (mockup value, kept verbatim — an opacity is not a colour token) **plus** the toggle's off state. Colour/opacity is never the sole carrier: the toggle position is the state control, and the row keeps its full hit areas.

## Interaction Contract

Baseline works with **JavaScript disabled** (Phase 2 D-09 rule). htmx and Alpine are enhancement only.

| Interaction | No-JS baseline | Enhanced |
|-------------|----------------|----------|
| Open the screen | Link from `/accounts` («Настроить группы»), `active_page=accounts` (D-02) | — |
| Toggle a group | `<form method="post" action="/accounts/{id}/groups/{gid}/toggle">` wrapping the toggle; redirect back | Alpine `x-on:change="$el.submit()"` — the existing Phase 1 pattern, instant, no confirmation (D-08) |
| Delete a group | Trigger form opens the modal; the modal contains a real POST form to `/accounts/{id}/groups/{gid}/delete`; redirect back | Alpine intercepts open/close only — the POST is always a real form |
| Синхронизировать всё | `<form method="post" action="/accounts/{id}/sync-groups">`; TG: synchronous, redirect returns with the plashka already populated; WA/MAX: sets `syncing`, redirect returns with the polling status block | Status block polls `hx-get` `every 5s` **only when** `status == 'syncing'` — the self-stopping pattern with all four 01-06 invariants, plus the paired stop/continue tests |
| Search | GET form via the `filters` macro; full server render from offset 0 | The macro's existing collapse behaviour ≤860px; no live-search debounce is added in this phase |
| Load more | Sentinel `hx-get="/accounts/{id}/groups/partial?offset={n}&limit=30&search={urlencoded}"`, `hx-trigger="revealed"`, `hx-swap="outerHTML"` | Same markup — the sentinel *is* the enhancement; without JS the first 30 rows and the true counter line remain usable |

**Placement rules:** the sync-result plashka and the delete modal live **outside** any element replaced by the poll (Pitfall 8 / T-11-04). The polled block is minimal — the status pill + in-flight line only. The counter line is not part of the scroll partial and never updates from it (D-04).

**Redirects:** `/groups` → 302 `/accounts` (D-01). All `RedirectResponse(url="/groups")` in `app/pages/accounts.py` (lines 734, 756, 759, 804) now target `/accounts/{id}/groups`.

## Responsive Contract

Breakpoints are the shipped Phase 1 set (860/900/1080). This screen adds no new breakpoint.

| Breakpoint | Behaviour |
|------------|-----------|
| > 860px | Header card: icon · identity · status pill · actions on one row. Group rows: avatar · name · marker · controls on one row |
| ≤ 860px | Shell collapses to the mobile shell (Phase 1, unchanged). The `filters` search collapses behind its button. Header card wraps: actions drop to their own row (`flex-wrap`), «Синхронизировать всё» stays first in DOM order |
| ≤ 400px | Group row wraps to two lines: avatar + name/sub on the first, marker + controls right-aligned on the second. Nothing scrolls horizontally, nothing is clipped |
| All widths | The list is card-rows at every width — it is not a `data-row` table, so no `[data-cell-label]` treatment applies. Rows are wrapping flex containers |

**Touch targets:** every interactive control ≥36px on its smallest axis — the «×» is 36×36, the toggle sits in a ≥36px label zone (Spacing exception 2), header buttons are 40px tall.

**Accessibility invariants:**

- The toggle is a real `<input type="checkbox">` behind a `<label>` — keyboard-operable and submittable without JS.
- Every icon-only control («×», toggle, ↻ glyph inside the CTA) carries `aria-label`/`title`; decorative SVG and dots carry `aria-hidden="true"`.
- Focus is visible on every control via `:focus-visible` + `--focus-ring` — never removed.
- The sync status block is `aria-live="polite"` so completion is announced without stealing focus.
- Colour/opacity is never the sole carrier of state: disabled row = opacity **and** toggle-off position **and** the toggle `title`; the missing marker = `--warn` colour **and** the caption text.
- The `rise` entrance animation sits inside the existing `prefers-reduced-motion` guard.
- Group names arrive from messengers (untrusted external input): Jinja2 autoescape everywhere, no pre-built HTML passed to macros (`test_no_unsafe_escaping`).

## Security Notes Carried Into the Visual Layer

- **Group names are untrusted external input** (they arrive from Telegram/WhatsApp/MAX): every render path — row, modal body, editor mark, search echo — relies on Jinja2 autoescape; no pre-built HTML is passed into macros. `test_no_unsafe_escaping` covers the new templates.
- **Ownership on every input** (Phase 2 rule / ASVS V4): page, partial, toggle, delete and sync all filter `user_id == user.id AND account_id == {id}`; the visual contract assumes a 404, never a leaked foreign row.
- The self-stopping poll is also the DoS guard: `hx-get` attributes exist **only** in the `syncing` branch, with paired stop/continue tests (T-06-01).
- The «Синхронизация уже выполняется» copy fronts the existing re-entry guard — the UI never offers a second concurrent sync.
