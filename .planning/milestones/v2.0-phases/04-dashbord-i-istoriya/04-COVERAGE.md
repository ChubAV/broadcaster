# API Coverage — Phase 04: Дашборд и история

> Full coverage by default. Opt-outs are explicit, reasoned decisions.

No external API integration: дашборд и история читают первичные данные проекта (SendLog, Schedule.next_run_at, MessengerAccount.status) из собственной БД, стороннего внешнего API/SDK фаза не подключает.

## Почему детектор сработал

Детектор `api-coverage` на `verify:pre` нашёл в области фазы два сигнала
`{verb: "(surface)", noun: "sdk"}` — оба на словосочетании «Docker SDK»:

- `04-01-PLAN.md:134` — «…не вызывает Docker SDK и НЕ кэширует результаты (D-37)»
- `04-05-PLAN.md:252` — «…Docker SDK на рендере не вызывается ни при каких условиях»

Оба вхождения — это ЗАПРЕТ вызова, а не интеграция. Источник запрета —
контракт Фазы 1 (D-19): «воркер онлайн» (DASH-05) читается из
`MessengerAccount.status` через `get_shell_context()`, потому что синхронный
Docker SDK блокировал бы event loop на рендере каждой страницы, а в тестах
сокет Docker недоступен. Запрет закреплён докстрингом `app/pages/common.py`
(строки 259-275) и тестом
`test_dashboard_page_has_no_second_source_of_the_sessions_number`
(разбор AST: среди импортируемых и вызываемых имён модуля SDK и сервис
управления контейнерами отсутствуют).

Детектор фиксирует упоминание вендорской поверхности и не читает отрицание
вокруг него — он намеренно fail-closed. Настоящая декларация и есть
предусмотренный справочником (`gsd-core/references/api-coverage.md`) способ
снять ложное срабатывание.

## Область фазы — все источники данных первичные

| данные экрана | источник | внешний вызов |
|---|---|---|
| метрики отправок за сутки (DASH-01) | `SendLog` (БД проекта) | нет |
| ближайшие отправки (DASH-02) | `Schedule.next_run_at` (БД проекта) | нет |
| живая лента событий (DASH-03) | `SendLog` через HTMX-поллинг своего же эндпоинта | нет |
| heatmap активности (DASH-04) | `SendLog`, агрегация в модуле аналитики | нет |
| воркеры онлайн (DASH-05) | `MessengerAccount.status` через `get_shell_context()` | нет — Docker SDK запрещён D-19 |
| фильтры/счётчик/экспорт истории (HIST-01…03) | `SendLog` (БД проекта) | нет |
| повтор отправки (HIST-04) | существующий механизм диспетчеризации (Celery/Redis, внутренний) | нет — протоколы отправки не трогаются |

Протоколы отправки в мессенджеры (Telethon, Baileys) — существующая
инфраструктура прошлых фаз; Фаза 4 их не расширяет и не переопределяет,
поэтому её поверхность внешнего API пуста.
