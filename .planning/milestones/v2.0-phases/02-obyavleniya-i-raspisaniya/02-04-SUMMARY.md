## Decisions Made

1. **Признак `required` снят с полей редактора.** htmx проверяет форму перед запросом и не отправляет невалидную. С `required` первое автосохранение пустого `/ads/new` не ушло бы вовсе — то есть черновик по D-03 не создался бы никогда. Поля формы на сервере тоже стали необязательными: пустой черновик — законное состояние.

2. **Публикует только явная отправка.** Именованная кнопка `save` — единственный признак, по которому обработчик отличает «Сохранить» от автосохранения. Эвристика «текст непустой» опубликовала бы объявление, которое пользователь только начал набирать, и планировщик разослал бы его по уже существующим расписаниям.

3. **Отказ по вложениям на htmx-пути отвечает 200, а не 400.** htmx не применяет внеполосные фрагменты из ответов с кодом ошибки: при 400 пользователь остался бы без единого объяснения, почему сохранение не состоялось. Сохранение при этом всё равно отклонено — запись не меняется, а индикатор переходит в состояние ошибки. На пути без JavaScript отказ по-прежнему 400: там тело ответа отрисовывает браузер, и подмена кода спрятала бы ошибку.

4. **Карточка «Содержание» выписана классами компонента, а не макросом `card_open`.** Индикатор автосохранения обязан стоять в шапке карточки у правого края (UI-SPEC), а слота в шапке у макроса нет. Макрос при этом не форкается и не перестилизуется: прецедент — кнопки в `ads/includes/ad_card.html`, выписанные классами там, где макрос не подошёл. Раскладка шапки в строку задана правилом, ограниченным сеткой редактора (`[data-editor] .card__head`), поэтому карточки остальных экранов не затронуты.

5. **«Сохранить» связан с формой атрибутом `form`.** Секция расписаний обязана быть СОСЕДОМ формы объявления (вложенные формы браузер молча отбрасывает), поэтому форма закрывается до правой колонки, а кнопка стоит в ней. Атрибут `form` — штатное средство HTML, и submit-событие с ним всплывает к форме, поэтому и htmx, и путь без JavaScript работают одинаково.

6. **Заголовок объявления вынесен за рамку предпросмотра.** Сигнатура отправки у всех трёх адаптеров — `send_message(group_id, text, images)`: заголовок в канал не уходит вообще. Внутри рамки он обещал бы отправку того, чего не будет. Как подпись панели он остаётся — она отвечает на вопрос «какое объявление показано», а не «что уйдёт».

7. **Порог счётчика зависит от наличия вложений.** Без вложений — предупреждение с 90% от 4096, с вложениями — с 1024, потому что выше этого порога подпись к медиа в Telegram без Premium гарантированно упадёт. Счётчик не блокирует сохранение и не обрезает текст: протоколы отправки эта фаза не трогает, а тихая обрезка текста была бы хуже ошибки.

8. **Редиректы пути без JavaScript различаются по намерению.** «Сохранить» завершает работу и возвращает в список; создание первым сохранением и убирание вложения оставляют пользователя в редакторе. Единый редирект в список выкидывал бы пользователя со страницы при каждом убранном вложении.
