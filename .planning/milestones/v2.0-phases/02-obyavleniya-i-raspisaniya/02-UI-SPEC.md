## Spacing Scale

Declared values for **all new Phase 2 markup** (multiples of 4 only):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap inside a chip (icon ↔ label), badge inner gap, gap between a day cell's letter and its state |
| sm | 8px | Gaps between day cells, time pills, account chips, attachment tiles; padding of the chip strip |
| md | 12px | Vertical gap between controls inside one group (label ↔ control, group-row list); horizontal gap in the collapsed schedule row |
| lg | 16px | Gap between editor sections; gap between the two editor columns; gap between blocks inside an expanded schedule card; gap between cards in the summary list |
| xl | 24px | Padding of the expanded schedule card body; vertical rhythm between the lead paragraph, the filter bar and the list |
| 3xl | 48px | Empty-state padding — inherited from the shipped `.empty` class, not re-declared |

**Fixed control sizes (all multiples of 4):**

| Control | Size |
|---------|------|
| Attachment tile / «+ ФАЙЛ» tile | 88 × 88 |
| Day cell | 44 × 36 (≤400px: 40 × 36) |
| Time pill | height 36 |
| Account chip | height 44 |
| Group row (checkbox row) | height 40 |
| Preview media thumbnail | height 120 |
| Summary-list day cell | 40 × 32 |

**Exceptions (documented, deliberate):**

1. **Phase 1 macros keep their mockup-literal values.** `.card` (padding 18/20), `.field` (gap 7), `.toggle` (38×22 track), `.empty` (48/20), `.filters`, `.modal`, `.badge` (4/9) ship with odd values transcribed from the mockup. Phase 2 **reuses these macros unchanged and does not restyle them** — re-snapping them to the 4-scale would be a Phase 1 refactor outside this phase's boundary.
2. **Toggle track is 22px tall**, below the 36px touch minimum. Mitigation: the toggle is wrapped in a `<label class="toggle">` whose full row is the hit area (≥40px tall in both the editor card head and the summary card head). No bare 22px hit target ships.
3. Mockup values 9/11/13/14/19/22px in the two reference sections are **rounded to the nearest scale step** (9→8, 11→12, 13→12, 14→16, 19→20→`.card` padding, 22→24). This continues the Phase 1 precedent that smoothed the mockup's fractional type steps.

## Typography

Four steps for all new Phase 2 markup. Two weights only.

| Role | Size | Token | Weight | Line Height | Applies to |
|------|------|-------|--------|-------------|------------|
| Label / mono meta | 11px | `--fs-xs` | 400 | 1.3 | Day-cell letters, time values, group member counts, schedule counts, «след. запуск», the autosave indicator, `+ ФАЙЛ` / `+ РАСПИСАНИЕ` / `+ ВРЕМЯ` / `БУДНИ` / `КАЖДЫЙ ДЕНЬ` / `УДАЛИТЬ РАСПИСАНИЕ` captions. Uppercase + `letter-spacing: .12em` where it is a field label, `.08em` where it is an action caption. |
| Body | 14px | `--fs-lg` | 400 | **1.6** | Field values, textarea, group names, account names, preview title text and preview body, hints, the summary-list lead paragraph |
| Section heading | 15px | `--fs-xl` | 600 | 1.2 | «Содержание», «Расписания», «Предпросмотр»; ad title in a summary-list card |
| Page title | 22px | `--fs-h1` | 600 | 1.2 | Shell head — inherited from Phase 1, not re-declared |

**Line height 1.6 for Body is deliberate, not the 1.5 default:** the preview must reproduce the composer. `.field__input--area` already ships at 1.6, so the preview paragraph matches it exactly; at 1.5 the preview would visibly re-wrap differently from the textarea and break ADS-06 ("ровно в том виде, в каком оно уйдёт").

**Inherited steps used through unmodified macros (not new declarations):** `.field__label` 10px, `.field__hint` / `.field__error` 12px, `.badge` 11px / `.badge--mono` 10px. Phase 2 introduces **no other size**. Fractional steps from the mockup (9.5 / 10.5 / 11.5 / 12.5 / 13.5px) are not used.

## Color

| Role | Value | Token | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `#08080b` / `#0e0e14` | `--bg` / `--surface` | Page background and card surfaces — the editor's two columns and every summary card |
| Secondary (30%) | `#12121a` / `#0f0f16` | `--surface-input` / `--surface-pill` | Inputs, attachment tiles, schedule-card shells, preview frame, unselected chips, expanded-card body |
| Accent (10%) | `oklch(0.72 0.19 310)` | `--accent`, `--accent-cta` | See reserved-for list below |
| Destructive | `oklch(0.68 0.19 25)` | `--danger` | Destructive actions and error copy only |
| Warning | `oklch(0.82 0.16 85)` | `--warn` | Draft / not-filled-in signalling only |

**Accent reserved for — exhaustive list. Any accent use not on this list is a checker failure:**

1. The single primary CTA per screen — «Сохранить» in the editor (`.btn--primary`, `--accent-cta`).
2. The **on** state of a toggle track (`--accent`) — schedule enabled, in both the editor card and the summary card.
3. Selection state of a choice control: day cell selected, account chip selected, group checkbox checked, filter option selected.
4. Focus ring (`--focus-ring`) on every keyboard-focusable control.
5. The status dot on a summary-list card **only** when the card's channel colour is not applicable.

**Explicitly not accent:** «Отмена», «+ ФАЙЛ», «+ РАСПИСАНИЕ», «+ ВРЕМЯ», «БУДНИ», «КАЖДЫЙ ДЕНЬ», «РАЗВЕРНУТЬ», «ВЫБРАТЬ ВСЕ», the character counter in its normal range, the autosave indicator when idle, the preview channel caption, all mono metadata. These are `--text-muted` / `--text-secondary`, with `--text` on hover only.

**Destructive reserved for:** «УДАЛИТЬ ОБЪЯВЛЕНИЕ» and «УДАЛИТЬ РАСПИСАНИЕ» captions (muted at rest, `--danger` on hover — mockup behaviour), the confirm button of a delete modal (`.btn--danger`), `.alert--error`, `.field__error`, and the character counter once the limit is exceeded.

**Warning reserved for:** the «Черновик» ad-status badge, the «НЕ ЗАПОЛНЕНО» schedule badge, the «Заполните группы, дни и время» hint, the «Объявление в черновике» marker in the summary list, and the character counter at ≥90% of the limit.

**Channel colours** come from `messenger_icon` (`--info` Telegram, `--ok` WhatsApp, MAX keeps its own gradient). They mark channel identity only and never mark state.

## Interaction Contract

Baseline works with **JavaScript disabled** (D-09). htmx and Alpine are enhancement only.

| Interaction | No-JS baseline | Enhanced |
|-------------|----------------|----------|
| Save ad | `<form method="post" action="/ads/{id}/edit">` with «Сохранить» | htmx autosave on `keyup changed delay:2s, change delay:2s`; the response swaps the preview + summary + indicator block (D-05, D-06) |
| First save on `/ads/new` | Plain POST creates the draft and redirects to `/ads/{id}/edit` | First autosave creates the draft and the URL becomes `/ads/{id}/edit` (D-03) |
| Add attachment | `<input type="file" multiple>` inside the form, submitted with it | `POST /api/uploads/image` per file, tile appended via DOM nodes (never `innerHTML`) |
| Remove attachment | Named submit button `name="remove_image" value="{key}"` — a real POST | Alpine removes the tile and the hidden input, autosave persists |
| Add / edit / delete a schedule | Real `<form method="post">` per schedule to the existing page routes | htmx per-schedule POST — each schedule saves separately and immediately (D-07) |
| Expand a schedule card | Link `/ads/{id}/edit?sched={sid}#sched-{sid}` — the server renders that card expanded and the others collapsed | Alpine intercepts the click and toggles in place; DOM identical either way |
| Toggle a schedule (editor and summary list) | `<form method="post" action="/schedules/{id}/toggle">` wrapping the toggle | Alpine `x-on:change="$el.submit()"` — the existing Phase 1 pattern, route unchanged (D-15) |
| Day presets БУДНИ / КАЖДЫЙ ДЕНЬ | Named submit buttons on the schedule form | Alpine checks the day checkboxes client-side |
| ВЫБРАТЬ ВСЕ groups | Named submit button | Alpine checks all visible group checkboxes |
| Change the account in a schedule | Radio + submit — the server re-renders the group list for the new account and **clears the previous group selection** | htmx swaps the group block; selection cleared identically |
| Filter / search the summary list | GET form via the `filters` macro (`Применить`, `Сбросить`) | Collapsible on narrow widths via the existing Alpine binding |

**Autosave delay: 2s** — the midpoint of the 1.5–3s window left to discretion in CONTEXT. Trigger is htmx-native (`delay:` modifier); no bespoke timer, no `beforeunload` handler (D-05).

**Attachment order** = the order of `Ad.images`, which is upload order and is exactly the send order. Removal preserves the order of the rest. No drag-and-drop in this phase (reordering is not in ADS-05, and a pointer-only affordance would break the no-JS baseline).

**No cap on the number of schedules per ad.** The section caption shows the count; nothing is hidden or truncated.

**Attachment cap: 10**, enforced on the server (D-13). The browser check stays as convenience only, and the «+ ФАЙЛ» tile is hidden once 10 tiles are present.

## Responsive Contract

| Breakpoint | Behaviour |
|------------|-----------|
| > 900px | Editor is two columns (`1.35fr / 0.85fr`, gap 16); the right column is sticky at `top: 96px` |
| ≤ 900px | Editor collapses to one column, sticky is dropped — **both rules already ship in `app.css:463-466`**. DOM order becomes the reading order: Содержание → Расписания → Предпросмотр → Сводка → Сохранить/Отмена → УДАЛИТЬ ОБЪЯВЛЕНИЕ. The preview must therefore stay **after** the composer in the DOM. |
| ≤ 860px | Shell collapses to the existing mobile shell (tabs, no sidebar) — Phase 1, unchanged. The `filters` macro collapses behind its «Фильтры» button. |
| ≤ 400px | Day cells shrink 44 → 40 wide; the day grid wraps to two rows |
| All widths | Attachment strip, chip sets, day grid and time pills are wrapping flex containers — nothing horizontally scrolls, nothing is clipped |

**Summary list is card-based at every width** — it is not a `data-row` table, so no `[data-cell-label]` treatment is needed. The ads list keeps its Phase 1 `data-row` + `[data-cell-label]` behaviour; only its status cell copy changes.

**Touch targets:** every interactive control in new markup is ≥36px on its smallest axis, except the inherited 22px toggle track, which is wrapped in a ≥40px label row (see Spacing exception 2).

**Accessibility invariants:**

- Day cells, group rows and account chips are real `<input type="checkbox">` / `<input type="radio">` visually hidden behind `<label>` — keyboard-operable and submittable without JS.
- Every icon-only control (`×`, toggle) carries `aria-label`; decorative SVG carries `aria-hidden="true"`.
- Focus is visible on every control via `:focus-visible` + `--focus-ring` — never removed.
- The autosave indicator is `aria-live="polite"` so a screen reader announces «Сохранено» without stealing focus.
- Colour is never the sole carrier of state: draft/enabled/incomplete each pair colour with text (a badge, a hint or a toggle label).
- `prefers-reduced-motion` is already honoured project-wide; the new `rise` entrance on the editor grid must sit inside that guard.

## Security Notes Carried Into the Visual Layer

These are Phase 1 debts closed in this phase (D-19…D-21) that have a rendering consequence, so the contract states them:

- Image keys come from user-controlled filenames and are stored in `Ad.images`. Any client-side rendering of a tile or preview thumbnail **must build DOM nodes and assign properties** — `innerHTML`, `outerHTML`, `insertAdjacentHTML` and `document.write` remain at zero in the project and the tests check the source.
- The attachment count limit is a **server** rule (D-13); the hidden «+ ФАЙЛ» tile is a convenience, never the enforcement point.
- The upload type check moves off the client-supplied `Content-Type` (CR-02); the error copy above is what the user sees when the server-side check rejects a file.
