# Requirements: Broadcaster

**Defined:** 2026-08-03
**Core Value:** Надёжно выполнять периодические рекламные рассылки в группы нескольких мессенджеров по заданному пользователем расписанию.
**Baseline:** Требования ниже зафиксированы по существующей реализации и считаются выполненными.

## v1 Requirements

### Доступ и профиль

- [x] **AUTH-01**: Пользователь может зарегистрироваться по email и паролю и подтвердить email кодом.
- [x] **AUTH-02**: Пользователь может войти в систему и сохранять авторизованную сессию.
- [x] **AUTH-03**: Пользователь может восстановить пароль через код, отправленный на email.
- [x] **PROF-01**: Пользователь может выбрать таймзону, применяемую к его расписаниям.

### Объявления

- [x] **ADS-01**: Пользователь может создавать и редактировать рекламные объявления.
- [x] **ADS-02**: Пользователь может прикреплять к объявлению изображение, размещённое в S3-совместимом хранилище.
- [x] **ADS-03**: Пользователь может просматривать и удалять свои объявления.

### Аккаунты мессенджеров

- [x] **ACCT-01**: Пользователь может подключить Telegram userbot-аккаунт через Telethon.
- [x] **ACCT-02**: Пользователь может подключить WhatsApp-аккаунт через изолированный Baileys worker.
- [x] **ACCT-03**: Пользователь может подключить MAX-аккаунт через изолированный pymax worker.
- [x] **ACCT-04**: Пользователь может видеть состояние подключения и отключать принадлежащий ему аккаунт.

### Группы

- [x] **GRP-01**: Пользователь может синхронизировать доступные группы подключённого messenger-аккаунта.
- [x] **GRP-02**: Пользователь может просматривать и выбирать группы для рассылки.
- [x] **GRP-03**: Система сохраняет состояние и диагностические сведения синхронизации групп.

### Расписания и доставка

- [x] **SCH-01**: Пользователь может создать расписание, связав объявление с выбранными группами.
- [x] **SCH-02**: Пользователь может настроить периодическую отправку по дням недели и времени в своей таймзоне.
- [x] **SCH-03**: Пользователь может включать, выключать, изменять и удалять расписания.
- [x] **SEND-01**: Система автоматически обнаруживает наступившие расписания и ставит отправки в очередь.
- [x] **SEND-02**: Система отправляет объявления в группы Telegram, WhatsApp и MAX через соответствующие адаптеры и воркеры.
- [x] **SEND-03**: Пользователь может просматривать историю и итоговый статус каждой отправки.
- [x] **SEND-04**: История отправки сохраняет снапшоты объявления и адресата независимо от дальнейших изменений исходных объектов.

### Биллинг

- [x] **BILL-01**: Пользователь может просматривать доступные тарифы Free, Basic и Pro и текущую подписку.
- [x] **BILL-02**: Система применяет тарифные лимиты к объявлениям, группам и использованию платформы.
- [x] **BILL-03**: Пользователь может пополнять баланс сообщений через интегрированную платёжную систему.
- [x] **BILL-04**: Система учитывает баланс и операции списания сообщений.

### Администрирование и эксплуатация

- [x] **ADMIN-01**: Администратор может просматривать пользователей и управлять их состоянием и подписками.
- [x] **ADMIN-02**: Администратор может просматривать историю отправок и собранные сведения о группах.
- [x] **OPS-01**: Операторы могут наблюдать метрики приложения и фоновых процессов через Prometheus и Grafana.
- [x] **OPS-02**: Операторы могут исследовать централизованные логи через Loki.
- [x] **OPS-03**: Система может быть развёрнута в development и production окружениях через Docker Compose и Nginx.

## v2.0 Requirements — Redesign

**Scope:** перевод всего интерфейса на макет `new_broadcaster_design.html` и связанные изменения модели работы с расписаниями, группами, историей и админкой. Протоколы отправки Telegram, WhatsApp и MAX не затрагиваются.

**Сквозной критерий:** раздел считается готовым только с адаптивной вёрсткой. UI-06 фиксирует адаптивные примитивы в дизайн-системе; проверка адаптивности каждого конкретного раздела входит в критерии приёмки соответствующей фазы.

### Фундамент интерфейса

- [ ] **UI-01**: Интерфейс использует единый набор дизайн-токенов (цвета, типографика, отступы, радиусы, тени) из макета.
- [ ] **UI-02**: Все страницы приложения отрисовываются через новый общий шелл `base.html` из макета.
- [ ] **UI-03**: Пользователь видит единую навигацию по разделам с подсветкой активного раздела.
- [ ] **UI-04**: Общие элементы (кнопки, поля, таблицы, карточки, бейджи статусов, модальные окна, пустые состояния) вынесены в переиспользуемые Jinja2-компоненты.
- [ ] **UI-05**: Точечные обновления интерфейса выполняются через HTMX/Alpine без полной перезагрузки страницы.
- [ ] **UI-06**: Дизайн-система содержит адаптивные примитивы (сетка, брейкпоинты, карточное представление табличных данных), применяемые во всех разделах.

### Объявления

- [ ] **ADS-04**: Пользователь может сохранить объявление как черновик, и содержимое черновика сохраняется автоматически во время редактирования.
- [ ] **ADS-05**: Пользователь может прикреплять к объявлению несколько вложений и удалять их.
- [ ] **ADS-06**: Пользователь может видеть предпросмотр объявления в том виде, в каком оно будет отправлено.
- [ ] **ADS-07**: Пользователь может настраивать расписания объявления (группы, дни, время) прямо в редакторе объявления.
- [ ] **ADS-08**: Пользователь может удалить расписание объявления из его редактора.

### Расписания

- [ ] **SCH-04**: Пользователь видит сводный список всех своих расписаний с объявлением, каналами, группами, днями и временем.
- [ ] **SCH-05**: Пользователь может включить или поставить на паузу расписание непосредственно из сводного списка.

### Аккаунты и группы

- [ ] **GRP-04**: Пользователь может открыть экран групп конкретного messenger-аккаунта.
- [ ] **GRP-05**: Пользователь может включать и отключать отдельные группы аккаунта.
- [ ] **GRP-06**: Пользователь может удалить группу из списка аккаунта.
- [ ] **GRP-07**: Пользователь может повторно синхронизировать группы аккаунта и увидеть результат синхронизации.
- [ ] **GRP-08**: Пользователь может добавить группу аккаунта вручную.

### Дашборд

- [ ] **DASH-01**: Пользователь видит метрики отправок за последние сутки.
- [ ] **DASH-02**: Пользователь видит список ближайших запланированных отправок.
- [ ] **DASH-03**: Пользователь видит живую ленту последних событий отправки.
- [ ] **DASH-04**: Пользователь видит heatmap активности отправок за неделю.
- [ ] **DASH-05**: Пользователь видит, какие воркеры его аккаунтов сейчас онлайн.

### История

- [ ] **HIST-01**: Пользователь может фильтровать историю по каналу, статусу и периоду.
- [ ] **HIST-02**: Пользователь может увидеть текст ошибки неуспешной отправки и скопировать его.
- [ ] **HIST-03**: Пользователь может выгрузить отфильтрованную историю в файл экспорта.
- [ ] **HIST-04**: Пользователь может повторить отправку из записи истории.

### Тарифы

- [ ] **BILL-05**: Пользователь может продлить текущую подписку.
- [ ] **BILL-06**: Пользователь видит потребление и остаток лимитов по четырём осям тарифа.
- [ ] **BILL-07**: Пользователь видит историю своих платежей.

### Администрирование

- [ ] **ADMIN-03**: Администратор видит подраздел «Обзор» с ключевыми показателями сервиса.
- [ ] **ADMIN-04**: Администратор видит подраздел «Пользователи» с поиском и фильтрами.
- [ ] **ADMIN-05**: Администратор может заблокировать и разблокировать пользователя.
- [ ] **ADMIN-06**: Администратор может войти под пользователем и вернуться в свою учётную запись.
- [ ] **ADMIN-07**: Администратор видит подраздел «Воркеры» с состоянием контейнеров по каналам.
- [ ] **ADMIN-08**: Администратор видит подраздел «Очередь» с состоянием очереди задач по каналам.
- [ ] **ADMIN-09**: Администратор видит подраздел «Логи» приложения и воркеров.
- [ ] **ADMIN-10**: Администратор видит подраздел «Платежи» со сводкой платёжных операций.
- [ ] **ADMIN-11**: Администратор видит инциденты сервиса.

## v2.1 Requirements

Отложено, не входит в roadmap v2.0.

### Уведомления

- **NOTIF-01**: Пользователь получает email-уведомление о сбое отправки.
- **NOTIF-02**: Пользователь получает email-уведомление о падении сессии мессенджера.
- **NOTIF-03**: Пользователь получает недельный email-отчёт.
- **NOTIF-04**: Пользователь получает email-уведомление при достижении 80% квоты.

### Устойчивость аккаунтов

- **WARM-01**: Система выполняет прогрев подключённого messenger-аккаунта.
- **WARM-02**: Система автоматически ставит расписания на паузу при падении сессии мессенджера.

## Out of Scope

| Feature | Reason |
|---------|--------|
| CRM и омниканальный inbox | Не относятся к зафиксированной функции периодических групповых рассылок |
| Чат-боты и автоматические диалоги | Продукт реализует плановую публикацию объявлений, а не conversational automation |
| AI-генерация рекламного контента | В текущей реализации и заявленной цели отсутствует |
| Нативные мобильные приложения | Текущий продукт предоставляет server-rendered Web UI |
| Отдельный SPA-фронтенд | Интерфейс остаётся серверным на Jinja2 — иначе слой рендеринга дублируется, а все существующие страницы переписываются заново |
| Изменение протоколов отправки Telegram, WhatsApp и MAX | Работающие сценарии доставки не входят в редизайн |
| Email-уведомления (сбои, падение сессии, недельный отчёт, 80% квоты) | Отложено в v2.1 — требует отдельной подсистемы доставки писем |
| Прогрев аккаунтов и автопауза при падении сессии | Отложено в v2.1 — затрагивает логику воркеров, а не интерфейс |
