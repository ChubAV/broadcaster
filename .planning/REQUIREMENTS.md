# Requirements: Broadcaster — milestone v2.2 «Номера аккаунтов»

**Defined:** 2026-10-08
**Core Value:** Надёжно выполнять периодические рекламные рассылки в группы нескольких мессенджеров по заданному пользователем расписанию.

**Цель вехи:** пользователь узнаёт свои аккаунты мессенджеров по номеру телефона, а не по внутреннему `#id`.

**Отправная точка (снята по коду 2026-10-08):** номер аккаунта нигде не хранится; подпись `#id` собирается в шаблонах
в ~17 местах без общего помощника; воркеры WA и MAX в `/status` номер не отдают; у MAX введённый номер затирается
`session_id` при подключении. Исследование — `.planning/research/SUMMARY.md` (решения владельца — там же).

---

## v2.2 Requirements

### Хранение

- [ ] **PHONE-01**: номер аккаунта хранится в каноническом виде E.164 (`+79991234567`) в отдельном поле аккаунта (ревизия `0023`, `down_revision = "0022"`); отсутствие номера — отдельное состояние «неизвестен»; уникальности по номеру нет
- [ ] **PHONE-02**: номер, указанный вручную, не затирается ни одним автоматическим источником (захват при подключении, дозаполнение) — в том числе при гонке с одновременной ручной правкой (условная запись, а не чтение-проверка-запись)

### Показ

- [ ] **PHONE-03**: пользователь видит номер аккаунта в международном формате (`+7 999 123-45-67`) вместо `#id` на всех своих экранах: список и карточки аккаунтов (включая карточки опроса синхронизации), шапка и `<title>` экрана групп аккаунта, чипы аккаунта в расписаниях, карточка истории и фильтр истории, подтверждение удаления аккаунта
- [ ] **PHONE-04**: когда номер неизвестен, пользователь видит подпись «Номер неизвестен»
- [ ] **PHONE-05**: когда у двух аккаунтов одного мессенджера одного пользователя подписи совпадают, рядом с подписью показывается приглушённый `#id`
- [ ] **PHONE-06**: администратор видит номер и `#id` аккаунта на экранах админки (воркеры, очередь, карточка пользователя, история пользователя)
- [ ] **PHONE-07**: CSV-экспорт истории содержит колонку «Номер»; колонка `account_id` сохраняется
- [ ] **PHONE-08**: у номера, указанного вручную, видна пометка «указан вручную»

### Ручная правка

- [ ] **PHONE-09**: пользователь может указать, изменить или очистить номер своего аккаунта в любой момент — с JS и без; ввод в свободной форме (`8…`, `+7…`, пробелы, скобки, дефисы); неверный ввод отвечает 422 с текстом ошибки по-русски и сохранённым введённым значением
- [ ] **PHONE-10**: после очистки номера пользователь снова видит «Номер неизвестен», и автоматические источники снова вправе заполнить номер
- [ ] **PHONE-11**: администратор под имперсонацией может править номер аккаунта пользователя (номер — подпись, на доставку не влияет); чужой аккаунт отвечает так же, как несуществующий

### Захват при подключении

- [ ] **PHONE-12**: новый аккаунт Telegram получает номер при подключении — и по QR, и после пароля 2FA — без повторного подключения к Telegram
- [ ] **PHONE-13**: новый аккаунт WhatsApp получает номер при подключении; LID за номер не принимается
- [ ] **PHONE-14**: новый аккаунт MAX получает номер при подключении; если мессенджер номер не отдал, используется номер, введённый в форме подключения, — как автоматический, не ручной
- [ ] **PHONE-15**: воркер старого образа, не отдающий номер, не ломает подключение: аккаунт подключается, номер остаётся неизвестным
- [ ] **PHONE-16**: рецепты `prod-deploy` и `prod-hard-deploy` пересобирают оба образа воркеров (WA и MAX)

### Дозаполнение существующих аккаунтов

- [ ] **PHONE-17**: администратор одной командой `just` дозаполняет номера аккаунтов без номера; ручные и уже заполненные номера не трогаются; повторный прогон ничего не меняет; в конце печатается итог по исходам (заполнено / ручной / номера нет / сессия мертва / воркер недоступен)
- [ ] **PHONE-18**: режим `--dry-run` показывает, что было бы записано, ничего не пишет и не поднимает контейнеры
- [ ] **PHONE-19**: по умолчанию опрашиваются только работающие воркеры WA/MAX; остановленные поднимаются только по явному флагу и гасятся после опроса
- [ ] **PHONE-20**: аккаунты Telegram опрашиваются последовательно, изнутри боевого контейнера, без риска разлогинить сессию (`AuthKeyDuplicatedError`)

### Приватность

- [ ] **PHONE-21**: номера не попадают в журналы приложения и воркеров и в вывод скрипта в открытом виде — только маска или признак наличия

## Future Requirements

Отложено, в дорожную карту v2.2 не входит.

- **PHONE-F1**: обновление автономера, когда номер сменили в самом мессенджере
- **PHONE-F2**: мягкое предупреждение о дубликате номера внутри (пользователь, мессенджер)
- **PHONE-F3**: слияние повторно отсканированных аккаунтов Telegram
- **PHONE-F4**: поиск и фильтр по номеру
- **PHONE-F5**: имя и аватар профиля аккаунта

## Out of Scope

| Feature | Reason |
|---------|--------|
| Уникальный индекс по номеру | Один SIM законно даёт TG+WA+MAX; TG при пересканировании создаёт новую строку — индекс уронил бы подключение и дозаполнение |
| Маскирование номера на экранах самого пользователя | Ломает узнавание — ровно то, ради чего веха |
| SMS-подтверждение ручного номера | Номер — подпись, а не учётные данные |
| JS-маска ввода номера | Свободный ввод с серверной нормализацией; правило проекта о деградации без JS |
| Перенос ручного номера при переподключении | Переподключение создаёт новую строку; решение владельца 2026-10-08 — требование о живой строке |
| Номер в текстах админ-инцидентов (`incidents.py`) | Решение владельца 2026-10-08 — вне объёма |
| Обновление Telethon / Baileys / pymax | Текущих пинов достаточно; протоколы отправки не трогаем |
| Сам выкат v2.2 на бой | Деплой-гейт владельца (D-26): только вместе с очередью ревизий `0020…0023` по R-08-06, пересборкой обоих образов и перезапуском воркеров в окно без рассылок |
