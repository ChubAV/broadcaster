# Requirements: Broadcaster — milestone v2.1 «HTMX-first»

**Defined:** 2026-08-26
**Core Value:** Надёжно выполнять периодические рекламные рассылки в группы нескольких мессенджеров по заданному пользователем расписанию.

**Цель вехи:** перевести всё письмо и все ручные обращения к серверу на htmx — так, чтобы ни одно действие пользователя не перезагружало страницу и ни один шаблон не собирал запрос руками.

**Отправная точка (снята по коду 2026-08-26):** 47 форм, из них через htmx не идёт **ни одна**; 36 POST-обработчиков; 127 `RedirectResponse`; 79 существующих `hx-*` атрибутов в 22 шаблонах, из них `hx-post` — 2; 6 ручных `fetch()`; `HX-Request` встречается во всей суите **1 раз** на 131 файл и ~1700 тестов.

## v2.1 Requirements

### Фундамент

- [x] **FOUND-01**: htmx обновлён с 1.9.10 до 2.0.10 заменой вендоренного файла, и тест утверждает версию по содержимому файла
- [x] **FOUND-02**: блок конфигурации htmx из шести ключей (`responseHandling` с правилом `422` **выше** `[45]..`, `historyRestoreAsHxRequest: false`, `allowNestedOobSwaps: false`, `reportValidityOfForms: true`, `historyCacheSize: 0`, явный `selfRequestsOnly: true`) стоит в `base.html` **и** `auth_base.html` перед подключением htmx, и каждая строка утверждается тестом
- [x] **FOUND-03**: `asset_version` пересчитывается при замене любого вендоренного JS-файла, а не только `app.css` — подмена `htmx.min.js` меняет `?v=` на его теге
- [x] **FOUND-04**: слой `respond()` в новом `app/pages/htmx.py` — единственное на проект объявление признака htmx; аргумент `redirect=` обязателен, поэтому обработчик без пути деградации не собирается как вызов
- [x] **FOUND-05**: реестр уведомлений `app/pages/notices.py` принимает КОД, а не текст; пять существующих микро-контрактов (`?error=`, `?saved=1`, `?reset=`, `?retry=`, `?sched_error=`) сведены в один `?notice=`
- [x] **FOUND-06**: OOB-область уведомлений подменяет СОДЕРЖИМОЕ (`hx-swap-oob="innerHTML:#notice"`), а не узел; заведены две области — вежливая (`role="status"`) и настойчивая (`role="alert"`); при отсутствии кода разметки нет вовсе
- [x] **FOUND-07**: гейт доступа `require_access` и зависимость имперсонации на `HX-Request` отвечают `HX-Location`, а не 302 и не JSON — иначе отказ выглядит как вложенная страница внутри карточки или как полная тишина

### Формы письма

- [ ] **FORM-01**: пользователь выполняет любое действие письма без перезагрузки страницы — все 47 форм идут через `hx-post`
- [ ] **FORM-02**: каждая форма остаётся рабочей без JS — сохраняет `method="post"` и непустой `action`, причём `hx-post` совпадает с `action` посимвольно, а `action` ведёт на маршрут, отдающий полный документ
- [ ] **FORM-03**: правка на месте (15 обработчиков класса A) возвращает фрагмент по `id` конкретной строки или карточки плюс побочные области через `hx-swap-oob`; контейнер целиком не перерисовывается
- [ ] **FORM-04**: навигационные действия (5 обработчиков класса B) возвращают `HX-Location`
- [ ] **FORM-05**: `/billing/subscribe` уходит на внешний адрес ЮKassa заголовком `HX-Redirect`, а не `HX-Location` — `selfRequestsOnly` заблокировал бы межсайтовый запрос
- [ ] **FORM-06**: подтверждение удаления работает через htmx во всех 16 местах одной правкой `components/modal.html`, и ответ снимает осиротевшую панель подтверждения вторым OOB-узлом с `hx-swap-oob="delete"`
- [ ] **FORM-07**: создание сущности вставляет её в список (`afterbegin`), не перерисовывая контейнер и не теряя позицию прокрутки
- [ ] **FORM-08**: ошибка валидации возвращает 422 с перерисовкой формы и эхо-возвратом введённого — пользователь не теряет заполненное
- [ ] **FORM-09**: единый макрос-обёртка формы раздаёт свойства качества, вместо того чтобы они проверялись ревью 47 форм поотдельности
- [ ] **FORM-10**: `HX-Retarget` и `HX-Reswap` применяются поимённо в перечисленных случаях, а не как общая практика — каждое применение делает поведение невидимым в шаблоне

### Свойства качества

- [ ] **QUAL-01**: двойное нажатие не создаёт второй записи — `hx-disabled-elt` на каждой форме письма, целью **только** `find button[type=submit]`; кнопка Отмены в панели подтверждения не блокируется никогда
- [ ] **QUAL-02**: пользователь видит, что запрос идёт — `hx-indicator` на каждой форме письма через один класс в `app.css` и один макрос, с порогом видимости через `transition-delay`
- [x] **QUAL-03**: отказ сервера и обрыв сети видимы пользователю — глобальные `htmx:responseError` **и** `htmx:sendError`; разметка плашки приходит с сервера заранее отрисованной скрытой заготовкой, скрипт только переключает атрибут, чем соблюдается действующее решение v2.0 «сборка узлами DOM, не строкой»
- [ ] **QUAL-04**: по каждой форме принято и записано решение о `hx-push-url` по конвенции трёх случаев: действие меняет ЧТО показано → `hx-push-url="true"`; меняет только данные → атрибута нет; адрес известен только серверу → заголовок `HX-Push-Url`
- [x] **QUAL-05**: снимки страниц не остаются в браузере после выхода из системы — `historyCacheSize = 0`
- [ ] **QUAL-06**: после подмены фрагмента фокус возвращается на элемент с тем же `id` — клавиатура и скринридер не теряют место

### Снятие ручного JS

- [ ] **FETCH-01**: загрузка изображения объявления идёт htmx-фрагментом вместо `fetch()` + JSON; успешно загруженные файлы остаются прикреплёнными, даже если часть отвалилась
- [ ] **FETCH-02**: мастер подключения Telegram по QR работает на HTML-фрагментах — опрос через `hx-trigger`, останов опроса ответом без `hx-trigger`, состояние мастера на сервере, `session_id` в скрытом поле при сохранённой серверной проверке владения
- [ ] **FETCH-03**: ручной сборки запросов в шаблонах не остаётся — `fetch(` в `app/templates/` равно 0

### Авторизация

- [ ] **SIGN-01**: 9 форм авторизации (вход, регистрация, подтверждение, повтор кода, восстановление пароля) идут через htmx
- [ ] **SIGN-02**: неверный код подтверждения или пароль перерисовывает форму с сохранением введённого вместо потери заполненного — заявленный выигрыш вехи на этом участке
- [ ] **SIGN-03**: успех авторизации уходит `HX-Redirect` через границу шеллов `auth_base.html` → `base.html`; `HX-Location` применяется только для `/impersonation/stop`

### Верификация

- [x] **GATE-01**: фикстура `htmx_client` (`HX-Request: true` + `follow_redirects=True`) существует, и каждый переведённый маршрут покрыт ПАРОЙ тестов: без заголовка → 302, с заголовком → 200 и `"<!DOCTYPE" not in response.text`
- [ ] **GATE-02**: 160 существующих утверждений `status_code == 302` становятся парами, а не заменяются — параметризованным обходом, а не 320 функциями
- [x] **GATE-03**: гейт единственности решения — каждый обработчик под `@router.post` идёт через `respond()` либо стоит в явном перечне исключений с обоснованием; множество обработчиков с `RedirectResponse` равно множеству, читающему `HX-Request`
- [x] **GATE-04**: гейты деградации — у каждого `<form>` с `hx-post` есть `method="post"` и непустой `action`; `hx-post` равен `action`; тег с `hx-post` обязан быть `<form>`; `action` ведёт на маршрут, отдающий полный документ
- [x] **GATE-05**: гейты свапа — на каждом `hx-post` есть `hx-target` либо `hx-swap="none"`; цель `hx-target` существует; каждый OOB-блок несёт `id`; один `id` не может быть одновременно `hx-target` и OOB-целью
- [x] **GATE-06**: гейт границы Alpine — узел с `x-data` никогда не является целью `hx-target`; множество целей собирается тем же обходом, чем гейт замкнут на себя
- [x] **GATE-07**: гейты безопасности ответа — AST-проверка, что правый операнд `response.headers["HX-*"]` есть литерал или f-строка с целыми (закрывает разом кириллицу в заголовке, инъекцию заголовка и открытый редирект); `|safe` и `Markup(` в шаблонах равны 0; `hx-vals` только через `| tojson`, формы `hx-vals='js:'` и `hx-on:` запрещены
- [x] **GATE-08**: `test_shell.py` утверждает версию htmx, каждую строку блока конфигурации, оба обработчика ошибок, обе `aria-live`-области и `samesite == "lax"` как записанное решение; гейт останова опроса — каждый фрагмент с `hx-trigger="every "` имеет парный без него; `test_no_manual_fetch_remains`
- [ ] **GATE-09**: девять именованных пунктов ручного UAT закрыты — замена вендоренного файла, 22 существующих `hx-get`-места и каскад infinite scroll, факт свапа и приземление OOB, снятие осиротевшей модалки, Alpine после свапа, `hx-indicator`/`hx-disabled-elt` визуально, `hx-push-url` с Back и F5, срабатывание глобального обработчика при 500 и при выключенной сети, атрибуты, собранные Jinja-условием
- [ ] **GATE-10**: тесты `*_degrades_without_alpine` получают парные `*_degrades_without_htmx`, а не переименовываются с подменой предмета

### Денежный путь

- [x] **PAY-01**: частичный уникальный индекс «не более одного незакрытого подписочного намерения» на `payments` построен — потолок становится свойством схемы, а не проверкой в коде, которую две одновременные отправки проходят обе

## v2.2 Requirements

Признано ценным, отложено осознанно.

### Правка на месте

- **EDIT-01**: пользователь правит значение по клику прямо в строке, без перехода в форму — единственный паттерн, где деградация без JS требует отдельной проектной работы (кнопка `hx-get` без JS мертва, нужен `<a href>`). Брать после того, как 47 форм переведены

### Прогресс загрузки

- **UPLD-01**: пользователь видит процент загрузки крупного файла — требует JS-обработчика `htmx:xhr:progress`, что прямо конфликтует с рамкой «минимум нового JS». В v2.1 берётся бинарный `hx-indicator`

### Браузерный стенд

- **E2E-01**: сквозные проверки в настоящем браузере покрывают то, что не доказуемо сервером (факт свапа, поведение Alpine после подмены, визуальные свойства). Это своя веха со своим решением — живой uvicorn, реальная БД, бинарники в CI и в Docker-сборке, вторая суита и флак; протаскивать внутрь v2.1 нельзя, её премиса — «ни build-шага, ни новой инфраструктуры»

## Out of Scope

| Feature | Reason |
|---------|--------|
| `hx-boost` на навигацию | Веха закрывает ПИСЬМО; навигация — независимая ось, её смешение размыло бы критерий готовности. Переходы по ссылкам остаются полной перезагрузкой |
| Снятие Alpine.js | 14 шаблонов с `x-data` остаются; перенос клиентского состояния на сервер — отдельная работа. В вехе Alpine получает только правило границы (узел с `x-data` не бывает целью свапа) |
| `jinja2-fragments` и любая новая Python-зависимость | Пакет требует `{% block %}`, а проект принуждает МАКРОСЫ двумя действующими гейтами; и он не касается трудной части задачи — ветвления 36 разнородных выходов. Веха получает 0 новых зависимостей |
| Playwright и браузерный стенд | ~1700 тестов идут на in-memory SQLite через `ASGITransport` без процесса и портов; стенд — живой uvicorn, реальная БД, бинарники в CI, вторая суита и флак. Новая операционная поверхность на вехе, чья премиса «ни build-шага, ни новой инфраструктуры». Отложено как `E2E-01` |
| Тосты через заголовок `HX-Trigger` | Starlette кодирует значения заголовков в latin-1 — проверено исполнением в venv проекта: первый же русский текст роняет ответ в 500. Плюс не деградируют без JS |
| `hx-confirm` | Вызывает браузерный `confirm()`, выброшенный в v2.0 вместе с 14 местами; возврат отменил бы записанное решение |
| Оптимистичный UI | У htmx нет отката. Для рассылок цена прямая: пользователь думает, что группа выключена, а объявление туда уходит |
| Морфинг-свап (`idiomorph`, `alpine-morph`) | Новый вендоренный файл при действующем правиле «внешних ресурсов 0»; проблема Alpine закрывается правилом границы дешевле |
| Расширение `response-targets` | В htmx 2.x расширения — отдельные пакеты; задача закрывается `responseHandling` и точечным `HX-Retarget` без нового файла |
| Свап всей страницы на каждое действие | Теряет позицию прокрутки и гасит раскрытые карточки; отменяет смысл фрагментного контракта |
| Плашка на каждый успех | Спам уведомлениями обесценивает канал; плашка — для того, что пользователь иначе не увидит |
| Полный отказ от `RedirectResponse` | 127 редиректов остаются как путь деградации; они не «легаси», а вторая половина двойного ответа |
| Изменение протоколов отправки Telegram, WhatsApp и MAX | Рамка, сохранённая с v2.0 — работающие сценарии доставки не трогаем |

### Фаза 9 — свидетельства к пересмотру состояний (заполнено планом 09-09)

таблицы выше и флажки в теле файла план 09-09 не трогал ни одной правкой — неприкосновенность
проверена сличением строк до и после (`git show HEAD:… | grep` против рабочего файла, оба вывода
пусты). Преждевременная отметка «выполнено» — ровно та ошибка, что породила третий пробел Фазы 9

который единственный видит и зелёную суиту, и заполненные таблицы отметок обхода, и этот раздел.

⚠️ **РАЗДЕЛ НАБРАН СПИСКОМ, А НЕ ТАБЛИЦЕЙ, И ЭТО МАШИННОЕ ТРЕБОВАНИЕ.** Проверка
неприкосновенности состояний сличает строки ТАБЛИЦЫ; табличные строки с теми же идентификаторами

#### ЗАПИСЬ ИСХОДА D-06 ↔ QUAL-06 — ОРИГИНАЛ (план 09-09, 2026-08-30)

  маршрута тумблера среди них нет.

  макроса-обёртки перестал передавать собственную цель блокировки и передаёт `sync='this:drop'`;
