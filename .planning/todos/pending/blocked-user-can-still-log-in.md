# Блокировка пользователя не действует — вход через страничный маршрут открыт

## Воспроизведение (прогон ревизии, временный тест удалён)

```
POST /api/auth/login   -> 403                                   ← правильно
POST /login            -> 302 + Set-Cookie: access_token=...    ← дыра
POST /api/ads (cookie) -> 201 Created                           ← заблокированный работает
```

## Где

- `app/pages/auth.py:48-56` — `login_submit` не читает `is_blocked`.
- `app/dependencies.py:26-41` — `get_current_user_id`, зависимость под ВСЕМИ
  закрытыми JSON-роутерами, не читает строку пользователя вовсе: проверяет
  подпись токена, а не состояние учётки.

- `collect_due_schedules` — про блокировку не спрашивает; расписания
  заблокированного продолжают рассылать.

## Почему это не поймал тест

`tests/test_admin.py:541` называется `test_blocked_user_cannot_login`, но
свидетельствует ОДИН из двух входов — только `/api/auth/login`. Имя теста
утверждает больше, чем его тело проверяет.

## Что чинить

Читать `is_blocked` там, где решается доступ, а не только на одном маршруте.
Кандидат на единственное место — `get_current_user_id`: через него проходят все
закрытые маршруты. Отдельно решить судьбу уже выданных cookie заблокированного
и путь рассылки.

Свидетель обязан покрыть ОБА входа и путь отправки — иначе починка повторит
дефект теста.
