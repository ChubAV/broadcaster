# Код ответа шагов отправки кода раскрывает существование учётки

Фаза 14 перевела отказы форм авторизации на 422 (решение D-03). На двух шагах отправки кода это
сделало исход различимым по одной строке статуса — однобитовый оракул перечисления адресов:

| Маршрут | Адрес занят / известен | Адрес свободен / неизвестен |
|---|---|---|
| `POST /forgot-password/send-code` | 200 (`respond_screen`, `app/pages/auth.py:841`) | 422 (`respond_field_error`, `:818`) |
| `POST /register/send-code` | 422 (`respond_field_error`, `:311`) | 200 (`respond_screen`) |

До фазы оба исхода отвечали 200 (`git show fd69a26a:app/pages/auth.py` — ноль `status_code=422`).
Тексты («Пользователь с таким email не найден», «Этот email уже зарегистрирован») раскрывали то же
и раньше — это давний долг `14-CONTEXT.md` §Deferred Ideas «Перечисление адресов»; новое здесь —
машиночитаемость без разбора тела. Пока нет сверки источника запроса (CR-01, R-14-01), оракул
достижим и со стороннего сайта.

Риск принят владельцем с исправленным основанием (`14-SECURITY.md`, R-14-02, 2026-10-07); этот
todo — адресат починки.

**Что сделать:** чинить вместе с перечислением адресов целиком — уравнять ОБА признака (текст и
код) у обоих исходов каждого шага, например общим ответом «если адрес подходит, код отправлен».
Только код уравнивать бессмысленно: текст раскрывает то же.

**Ловушка:** правило
`tests/test_pages/test_auth_transport.py::test_an_unknown_email_keeps_the_address_and_answers_422_on_both_transports`
закрепляет 422 на неизвестном адресе, а `tests/test_pages/test_registration.py::test_send_code_rejects_existing_email`
— 422 на занятом (`assert response.status_code == 422`). Починка их покраснит — это ожидаемо:
правила переписываются вместе с поведением, а не возвращают 422 ради зелени.
