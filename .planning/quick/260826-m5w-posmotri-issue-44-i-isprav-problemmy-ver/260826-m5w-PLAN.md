<objective>
Иконка мессенджера в шапке свёрнутой карточки расписания перестаёт сжиматься и
обрезаться: она исключается из общего правила сводки, писавшегося под текст.

Purpose: сегодня на `/ads/{id}/edit` круглые глифы WhatsApp / MAX / Telegram в блоке
«Расписания» срезаются по левому и правому краю, как только сводка перестаёт
помещаться в строку (issue #44). Причина в одной строке — `app/static/css/app.css:1782`:

```
.sched-card__sum > * { min-width: 0; overflow: hidden; text-overflow: ellipsis; }
```

`.sched-card__sum` — flex-контейнер (`app.css:1776-1781`), и его ПЕРВЫЙ ребёнок в
`app/templates/ads/includes/sched_card.html:107` — не текст, а вызов
`messenger_icon(account.type, size='avatar', show_label=false)`, отдающий
`<span class="msg">` с 30-пиксельным `<svg class="msg__glyph … avatar">` внутри
(размер приходит из `.avatar`, `app.css:623-628`). Общее правило выдаёт этой обёртке
`min-width: 0` — разрешение сжаться ниже содержимого — и `overflow: hidden`, из-за
которого не влезший 30-пиксельный кружок не переполняет обёртку, а ОБРЕЗАЕТСЯ.
`.msg__glyph { flex: none; }` (`app.css:1499`) держит svg внутри `.msg`, но саму `.msg`
как flex-элемент сводки не защищает ничто — в отличие от соседних блоков, где ровно
этот приём уже применён: `.sched-item__head > .msg` (`app.css:2006-2008`) и
`[data-group-row] > .avatar` (`app.css:2147-2150`).

Output: одно правило-исключение в таблице стилей с комментарием-объяснением, одна
именованная регрессия, держащая ОБА конца контракта (иконка не сжимается, сводка
по-прежнему обрезается многоточием), и записанное распоряжение по второй находке
со скриншота.
</objective>
